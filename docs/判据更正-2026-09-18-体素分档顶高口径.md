## 更正 ①:`shape.max(Y)` → 中心列顶高(已被更正 ② 取代,保留存档)

### 原判据(task-83 任务书原文,逐字)

> 以根因②为前提做"数据驱动"分类:用 `state.getCollisionShape(level, CURSOR).max(Direction.Axis.Y)`
> 取**实际顶高 h**

### 实测证伪

用 1.20.1 官方映射 jar 对 `StairBlock` 反编译实测:`TOP_AABB/BOTTOM_AABB` 满铺,
`OCTET_*` = 0.5³ 角块,`makeShapes` 对 bottom 档把角块 y 上移 0.5 ⇒ **楼梯 `max(Y) = 1.0**
⇒ 按字面 max-Y 会被判 `CODE_SOLID`,与任务表第 2 行"楼梯 → 中低档"冲突;
而耕地/土径 `FarmBlock = 15/16` 又必须 SOLID ⇒ **单标量无法同时满足两行**。

### 当时的更正

取**中心列顶高** = 严格包含格中心 (0.5, 0.5) 的 AABB 最高 `maxY`
(严格不等号因楼梯角块边界恰落在格中心)。Lead 当日批准:"任务书那张表才是要求,
max-Y 只是代理指标 ⇒ 表优先"。

### 后续

该口径**在更正 ② 中被取代**——真 registry 实测发现它在"两盒共面"处失效(见下)。

## 更正 ②:`getCollisionShape`(碰撞形)→ `getOcclusionShape`(遮挡形)占比 + 两条守卫

### 原判据(更正 ① 之后实际实现的口径)

用**碰撞形**取中心列顶高。

### 实测证伪(真 1.20.1 registry;`VoxelRealRegistryContract` 的 MEASURED 行为原始证据)

1. **原版雪层的碰撞形比外观/遮挡形矮一层**(coll = vis/occ 下移 2/16)。实测:
   - coll:1/2/3/8 层 = 空 / 0.125 / 0.25 / 0.875
   - occ(= vis):1/2/3/8 层 = 0.125 / 0.25 / 0.375 / 1.0
   任务表"雪 ≤2 层 → EMPTY"是按**外观/遮挡形**说的(occ 正好 0.125/0.25);
   用 coll 会变成"≤3 层 EMPTY、8 层 0.875 → VEG(偏透)"。
2. **"中心列严格包含"在两盒共面处同时排除两个盒**:`OAK_STAIRS[half=top]` 的
   碰撞形 = `[0,0,0→1,1,0.5] ∪ [0,0.5,0.5→1,1,1]`,两盒的面都恰好落在 z=0.5
   ⇒ 中心列 h = 0 ⇒ **`CODE_EMPTY` = 漏光**(危险方向)。

### 裁定(Lead,2026-09-18)

**占比用 `occ` 形**(我们算的是"光被挡多少",遮挡形才是这件事的真源)+ 两条守卫,
**顺序写死**:

| # | 规则 | 为什么顺序不能换 |
|---|---|---|
| 1 | `coll` 空 ⇒ `CODE_EMPTY` | 绊线/铁轨/蛛网 `occ` 非空(蛛网甚至满格)⇒ 先按占比会把蛛网判 SOLID |
| 2 | `coll` 最大 `maxY > 1.0` ⇒ `CODE_SOLID` | 栅栏/墙碰撞柱 1.5 而 `occ` 只有 1.0 格高(占比 0.0625/0.25)⇒ 不设守卫会漏光 |
| 3 | 其余按 `occ` 实心体积占比 | ≤0.25 ⇒ EMPTY;0.25~0.9 ⇒ VEG;≥0.9 ⇒ SOLID |

### 为什么占比口径下"共面失效"不再咬人

体积 = 各盒体积之和,与"面落在哪里"、"朝向"都无关(top 楼梯 0.75 ⇒ VEG)。
**后来者若要重写"中心柱/中心列"这类点采样判据,请先复现 top 楼梯这一例**
(它是把"危险方向 = 漏光"暴露出来的那一例)。

## 原版事实单列(会再咬人)

**雪的碰撞形 ≠ 外观/遮挡形:`coll` 比 `vis`/`occ` 矮一层(2/16)。**
玩法决定(让玩家能走上雪层)。任何"拿碰撞形当遮挡/外观代理"的判据都会让雪的影子偏小。
实测(层数 1..8):`coll` = 空 / 2 / 4 / 6 / 8 / 10 / 12 / 14(/16);`occ` = 2 / 4 / 6 / 8 / 10 / 12 / 14 / 16(/16)。
