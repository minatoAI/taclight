## TL;DR

1. **左右不对称的元凶是"自己的身体挡了自己的灯"**:第三人称下灯锚在玩家头旁(设计如此,
   偏右 0.22m),SSO 遮挡测试对第三人称是开启的,而 0.6m 贴灯豁免圈只护住头部——躯干和腿
   把光锥左下方整个切掉,形成一条贴着身体轮廓的硬阴影边。第一人称有 `vis=1` 同轴豁免
   (`taclight_common.glsl` `dot(lightView,lightView) < 0.25`),第三人称没有对应豁免——**设计缺口**。
2. **"过曝糊死"是能量设计问题,不是 shader 写错**:半径 56m 的反平方衰减在 4~8m 室内距离
   几乎不衰减(atten≈0.94),乘上 intensity 6 + 镜面 + 体积光 + 大半径 bloom,整块锥形足迹
   被推进饱和平台。实测截图 10% 画面饱和在 224/255,纹理全毁——"右半"其实是"完全过曝区"。
3. **移动闪烁的主因是雨**:`gbuffers_weather` 声明 `DRAWBUFFERS:0123`,而 Iris 对
   colortex1/2/3 的写入**不做混合**——每一条下落的雨丝都在用"雨丝的法线/albedo/视图位置"
   整块覆写墙面像素的 G-Buffer 数据,composite 照着这些每帧都在刷新的数据打光 = 被照面
   亮纹随雨丝跳舞。原版 1.20.1 的雨是写深度的(`COLOR_DEPTH_WRITE`),与 gbuffers_weather
   头注释"雨雪粒子不写深度"的前提相反,等于这层从未被正确处理过。
4. **参考项目根本没做"真聚光"**:HandheldMoon 的"光锥"= 把 DynamicLightsReforged 一族的
   **方块级点光**加一个角度遮罩(1 格分辨率、逐 tick 重建区块),再叠一个**纯 2D 屏幕中心
   提亮**的 post pass(蜘蛛视觉同机制)。它没有逐像素锥、没有体积光、没有真正的墙面光斑——
   这正是它"看起来没毛病"的原因:它回避了所有难点。我们的 SSBO 路线是唯一能做真聚光的,
   问题是踩了三个具体的坑(上面 1~3),不是路线错了。
5. 多人旁观测试环境已建成并跑通契约:**状态真源 = Player SynchedEntityData 两个布尔**
   (`/taclight light <on|off|toggle> [player]` 或 L 键自动上报),观察端上传器遍历
   `level.players()` 收集远程灯;`gradlew runServer + runClient + runClientObserver`
   三进程拓扑,RCON 驱动,详见 §8。

## 2. 根因逐条(代码定位 + 机理)

### R1 过曝平台:半径 56 的反平方在室内"失明"

`pack/shaders/lib/taclight_common.glsl:91-97`:

```glsl
float k = TACLIGHT_ATTEN_K / max(radius*radius, 1e-4);   // k = 2/56² ≈ 6.4e-4
```

atten(4m) ≈ 0.99、atten(8m) ≈ 0.94——**在房间尺度上衰减根本不存在**。56m 半径是为
"照远"设计的,但室内每一面墙都在 4~8m,于是整个锥形足迹以近乎满强度点亮,再叠加:
GGX 镜面(未钳制,smooth 表面出亮斑)、M3 体积光(直接加进 c0,未经 soft_knee 压缩)、
bloom 链(阈值 0.55,大半径 13tap)——最终把足迹推成 224 的平顶。
`taclight_soft_knee`(G=2.0)只作用于 M1 表面项且上限 0.5,压不住这个总量。

这不是"shader 不行",是**能量标定**:真手电在 4m 墙上的中心照度与边缘比、近墙与远墙比,
都需要衰减曲线在 3~15m 内有明显斜率。

### R2 第三人称自体阴影:硬边 + 随身晃动

`taclight_common.glsl:136-142`(M1 主循环):

```glsl
if (dot(lightView, lightView) < 0.25) { vis = 1.0; }   // 灯距相机 <0.5m 才豁免
else { vis = taclight_sso(fragView, lightView); }
```

- 第一人称:灯在眼前(≈0.44m)→ 恒豁免,无自遮挡(铁律 8)。
- 第三人称:灯锚玩家头(`ClientSpotlightUploader` TP 分支 `getEyePosition + handheldOffset`),
  距相机 3~5m → **SSO 全开**。SSO 的贴灯豁免只有 `TACLIGHT_SSO_SELF_FREE=0.6m`,护得住头,
  护不住 1m 之外的躯干和腿(它们在 depthtex1 里是遮挡系数 1.0 的实体)。
- 灯又设计成偏右 0.22m(`handheldOffset` 契约)→ 身体在灯的左下 → **阴影恰落在锥的左下**,
  与截图台阶方向完全吻合。
- SSO 内部:16 步 + IGN 抖动 + 陡消光 `pow(1-occ*2.4, 2)`(`taclight_common.glsl:155-182`)。
  台阶边缘的像素每帧随抖动相位翻动 → 边缘噪闪;身体随移动摆动 → 边界扫动 = "忽明忽暗"。

这条同时解释"不对称"和"移动闪烁"的一大半。**修复方向**(按侵入度):
a. TP 也走"自体豁免":从片元到灯的射线与玩家包围盒(胶囊)求交,交点在灯前 1.2m 内按半影
   弥散处理(豁免或弱化);
b. 把 `TACLIGHT_SSO_SELF_FREE` 从球改成"以灯为端点、沿灯后方向 1.2m 的胶囊"——物理上灯贴着
   头,自身半影本就该全弥散(与铁律 8 同一物理依据);
c. 收紧 SSO 陡消光系数(2.4 → 1.2)并步数提到 24,边界过渡变宽,噪闪幅度下降。

### R3 雨:G-Buffer 被雨丝逐帧覆写(闪烁主因)

`pack/shaders/gbuffers_weather.fsh:8`:`/* DRAWBUFFERS:0123 */`,写 colortex0~3。
Iris/Oculus 对 gbuffers 的辅助附件(colortex1/2/3)**没有混合状态,是整块覆写**。
而原版 1.20.1 雨渲染(`RenderType.weather`)是 `TRANSLUCENT_TRANSPARENCY + COLOR_DEPTH_WRITE`
——**写深度**。于是 composite(`depthtex0` 采样)在雨丝像素上拿到的是:

- 深度 = 雨丝(半空,2~3m,每帧下落刷新);
- 法线 = 雨丝四边形的面法线(朝相机);albedo = 雨纹理 RGB(白色调);smoothness=0.3;
- colortex3 = 雨丝视图位置 + 遮挡系数 1.0。

→ 每条雨丝在"被照亮的墙"上变成一根亮白竖纹,随雨下落逐帧换位 = 被照面整体闪烁;
"似乎是什么在刷新"的直觉完全正确——**刷新的就是雨丝栅格化**。
修复方向:weather pass 只写 colortex0(DRAWBUFFERS:0)且 `discard` 掉纹理 alpha 低的片元
(或干脆不参与 G-Buffer,雨中观感交给 M3 体积光——头注释本来就指望这个),另把
composite 的表面深度从 `depthtex0` 换成"depthtex1(实心)优先、无则 sky"的策略讨论一并做。

### R4 体积光束(M3)的三个次级缺陷

`pack/shaders/composite1.fsh`:

1. **表面衰减函数被直接搬进体积积分**:`taclight_attenuation(d, radius)` 以"采样点到灯心
   距离"自变量——射线在灯旁掠过的一两步(第一人称灯锚眼前 0.35m!)就拿到 atten≈1,
   整条射线的散射被近场支配。正确做法是体积版衰减(对近场做最小距离 clamp,例如
   `max(d, 0.75)`),或解析的"点光沿线积分"公式。
2. **TP 枪灯 fallback 锚在相机**:`ClientSpotlightUploader` 枪灯 else 分支用的是**相机**
   `eye + gunFallbackOffset`——第三人称时等于把灯挂在自己镜头上,整屏锥内近场全亮
   (距灯 1m 内的采样全部atten≈1)。远程枪灯本轮已改锚玩家眼位,本地 TP 分支建议一并修。
3. 24 步 IGN 抖动:静止时靠 bloom/颗粒融合,移动时屏幕固定噪声 × 移动几何 = 残影闪烁
   (性质同 R2 的 SSO 抖动,步数低时的固有代价,提步数/切时间抖动可缓解)。

### R5(次要)自适应曝光会放大"忽明忽暗"

`composite2.fsh` 的 8×3 网格眼适应(`TACLIGHT_EXPOSURE_LOCK` 当前编译期=1,锁定中)。
若解锁做 A/B,光斑扫过测光格 → 全屏曝光反向泵动,主观上也是"忽亮忽暗"。验收几何问题时
保持锁定;评"观感"时解锁,但要知道它叠加了放大效应。

## 3. 两个参考项目的真实实现(拆解)

### 3.1 DynamicLightsReforged(= LambDynamicLights 家族,1.20 分支已切)

机制一句话:**把动态光源直接改写进"光照坐标(lightmap coordinate)"整数**。

- 光强查询:`LambDynLights.maxDynamicLightLevel` —— 对每个被查询的方块,光级 =
  `luminance × (1 − dist/7.75)`,线性衰减、全向、**默认无遮挡检测**(穿墙)。
- 注入点:mixin 进实体渲染与 Sodium/Embeddium 光照管线,把方块光 nibble 换成
  `dynamicLightLevel × 16`(保留小数精度,`getLightmapWithDynamicLight`)。
- 生效方式:光级变了 → `scheduleChunkRebuild` 重build周围区块网格(每 tick,光动就重建)。
- 光影包兼容:光影包照常采样 lightmap 纹理,动态光只是改变了喂进去的坐标——**对光影包
  完全透明,但它永远只能是"方块级、全向、无形状"的点光**。

### 3.2 HandheldMoon(依赖上述动态光,在其上加方向性)

三层结构,一层比一层"取巧":

1. **体素级锥形遮罩**(`DirectionalLightMixin` → `LightHandler.entityLight`):混入
   `maxDynamicLightLevel`,给点光加角度项——方块中心相对玩家视线的夹角超出 0.5~0.7 rad
   渐灭;距离 1−t² 衰减;开 `LIGHT_OCCLUSION` 时对每个方块做一次 `level.clip` 射线检测
   遮挡。**分辨率 = 1 格**:墙上的"光斑"是块状的,靠原版顶点插值才显得平滑。
2. **逐 tick 区块重建**(`Light.java`):对每个光源周围 5×5 section 每 tick
   `scheduleChunkRebuild`——移动时持续重建网格,这是该家族的固有代价(也是它们"动起来
   会抽搐"的来源)。
3. **"光锥"其实是个 2D 特效**(`event/Shader.java` + `shaders/post/flashlight.fsh`):
   用原版 PostEffect 管线(蜘蛛视觉同机制)在**屏幕中心**画一个 `smoothstep` 圆,圆内做
   gamma 提亮(`pow(color, 1/(1+boost))`)。它不与任何几何相交、随视角转动做反向惯性偏移
   ——**屏幕上的亮圈,不是世界里的光**。
4. 多人为什么"天生能工作":开关状态存在**手持物品的数据组件/NBT**里(物品随背包同步),
   所有客户端都能对任何玩家本地判定 `isUsingFlashlight`;位置/视线是实体同步自带的。
   零自定义网络包——聪明的取巧,但也决定了它做不了"别人的灯在你的墙上打出真光斑"之外的
   任何精度。

### 3.3 对本项目的启示

- 它们验证了:**多人可见性不需要服务端真正"知道"灯**——只要开关状态进了同步数据
  (它们用物品 NBT,我们用 SynchedEntityData,后者更干净:支持命令/RCON/权限控制),
  位置与视线本来就在实体同步里,其余全是客户端各自渲染。
- 它们也证明了回避难点的代价:块状光斑、无体积光、移动重建抽搐、2D 假锥。**我们不需要
  改道,需要把 SSBO 路线的三个坑(R1/R2/R3)填掉。**

## 4. 概念澄清:点光源与聚光灯的差别,难点到底在哪

你的直觉"光影包都能做点光源,聚光灯只差一步"——前半句对,后半句差得远。
光影包里的"点光源"绝大多数是两种东西:

| 所谓的点光源 | 实质 | 离聚光灯的距离 |
|---|---|---|
| 原版方块光(火把/萤石) | 烘进 lightmap 的体素光场 | 隔着一整个"光源抽象":它没有位置向量、没有方向、没有 1/d²,是预计算的体素场;动态光 mod 只是往里塞值 |
| held light / 手持光源 uniform | gbuffers 里一个写死方向的单灯,per-fragment `dot(N,L)×衰减` | 几何上确实一步能加 cos 锥项;但**没有阴影**——光穿墙;且只有一个灯、写死在包里 |

聚光灯真正多的三样东西,才是难点:

1. **阴影(可见性)**:一动光源的阴影 = 每像素从片元回光源的可见性判定。原版管线没有
   "任意光源的 shadow map"——Iris 的 shadow pass 绑死太阳/月亮方向(`shadowtex` +
   `shadowLightPosition`),转不到你的手电上。可行解只有屏幕空间(SSO,本项目现状,
   视锥外遮挡者失明)或不做(参考项目选择不做,光穿墙)。
2. **体渲染**:光束观感 = raymarch,而 1/d² 在灯附近发散,必须正则化(R4.1 就是没正则)。
   光影包里的"god rays"是太阳方向的屏幕空间径向模糊,不是真体散射——没有现成代码可抄。
3. **时间稳定**:逐像素、逐帧、动光源,没有 TAA(Iris 光影管线不提供历史缓冲给 composite
   自由使用)——抖动噪声(IGN)是唯一廉价的去带状手段,代价就是移动时的噪闪。
   参考项目用"1 格分辨率 + 原版插值"天然规避了这一切——它们不是做得好,是做得糙。

**结论:shader 不是不适合,是"这套管线里没有现成的聚光灯零件"**。点光源 mod 的简单是
因为它们把光退化成"无方向、无阴影、块级"才简单;我们的路线(SSBO + deferred composite)
是目前 Iris/Oculus 生态里做真聚光的唯一可行架构,修的三个点都是具体缺陷而非路线问题。

## 5. 技术路线总表(含未采用项与理由)

| 路线 | 原理 | 优点 | 缺点 | 判定 |
|---|---|---|---|---|
| A. lightmap 注入(DLR/HandheldMoon) | 改 lightmap 坐标 + 区块重建 | 任何渲染器/光影包通吃;多人零成本;便宜 | 方块分辨率;全向(加角度遮罩=HandheldMoon 的块状锥);无逐像素边缘;移动重建抖动;无体积光 | 不符合"真锥形"目标,仅可作低端兼容层 |
| B. 2D 屏幕特效(HandheldMoon post) | 屏幕中心 radial 提亮 | 极便宜;永不穿帮(不与几何交互) | 不是光:无墙面光斑、无遮挡响应、无深度感 | 已否决(假效果) |
| C. 前向 uniform 单灯(gbuffers 手电) | 包里写死 uniform,gbuffers 直接加光照 | 无需 deferred/SSBO;兼容大部分包 | 无阴影(穿墙);单灯;要改写全套 gbuffers;与别的光影包互斥 | 不符合"自研包全功能"定位 |
| D. Deferred G-Buffer + SSBO(本项目) | 每帧灯姿态→SSBO;composite 逐像素锥光 + raymarch 体积 | 逐像素真锥;多灯;体积光/风络/bloom 全链路;枪灯精确位姿 | 需要自研包;阴影只有屏幕空间;时间稳定性要自己管;踩坑面大(见 §2) | **主路线,保持** |
| E. 影子贴图转向 | 用 Iris shadow pass 做灯的阴影 | 真硬阴影 | Iris/Oculus 的 shadow camera 绑死日月方向,无法指向任意动光源;改造等于分叉渲染器 | 不可行(生态限制,非理论限制) |
| F. 光源方块/服务端布光 | 沿锥放 light 块/light block | 多人天然可见;原版阴影 | 逐格离散;放块=改世界(副作用、性能、权限);移动时刷块延迟 | 已否决(副作用) |

选型建议维持 D;若将来要"低配兼容模式",A 可以作为退化实现(项目红线:不抄参考项目代码,
只复用公开数学)。
