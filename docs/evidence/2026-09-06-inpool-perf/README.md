# 2026-09-06 光池内(in-pool)掉帧定位:开灯 240→40 帧的原因

## 用户现象
开灯前 ~240 fps,开灯后直接掉到 ~40 fps(4K,A 端 Dev 视角,站在光池里)。

## 场景与方法
- A 端窗口 3841×2130(`!shot` PNG 实测,≈4K 客户区);**双灯 on**(Dev+ObserverB);
  cone 20°(用户手调);voxel on;`!bench` 3s×3 取中位;**同机位同视角**受控 A/B
  (中继逐条下发,每臂之间只改一个变量)。
- 机位 = 用户实机站位:光池内看向被照地面/墙面 → 近全屏像素通过锥门进入
  composite1 逐采样路径(这正是掉帧的前提条件,见坑 112)。

## 结果(fps 中位,ms=1000/fps)

| 臂 | 配置 | fps | 帧时 | 差分 |
|---|---|---|---|---|
| 1 | 灯关(cone20 无影响) | 354.5 | 2.82ms | 基线 |
| 2 | 灯开×2 / VL_STEPS 64 | 28.4 | 35.2ms | **开灯 +32.4ms** |
| 3 | 臂2 + cone 20→8 | 39.1 | 25.6ms | 锥收窄省 9.6ms |
| 4 | 臂2 + beamonly on(无表面照明) | 29.4 | 34.0ms | 表面照明仅 ≈1.2ms |
| 5 | 臂2 + voxel off(无灯侧 DDA) | 69.2 | 14.45ms | **灯侧 DDA ≈20.6ms** |
| 6 | 臂2 + VL_STEPS 64→32 | 55.3 | 18.1ms | **步数减半省 17.1ms** |

一致性:臂6 灯开销 15.3ms ≈ 表面 1.2 + raymarch(无 DDA)~5.8 + DDA ~10.3(臂5 的
一半),各臂相加在 ±1ms 内闭合。

## 结论(费曼版)
1. **开灯掉帧的大头不是"光多亮",是遮挡检测(体素 DDA)的次数**:体积光每个采样步
   都要对每盏灯跑一次灯→采样点的 DDA 光路追走;站在光池里 = 全屏像素都在跑,
   64 步 × 2 灯 × 800 万像素 → ≈20.6ms,占开灯总开销的 2/3。
2. **远景测的"DDA≈0.13ms"(09-06 凌晨 4K 复测)不可外推到光池内**——那时绝大多数
   像素被便宜门挡在 DDA 之前;覆盖率和成本是平方级关系(坑 112)。
3. **VL_STEPS 64→32 = 同机位 28.4→55.3 fps**,DDA 与 raymarch 都随步数线性减半。
   视觉:当前宽锥(用户 15-20°)下实拍无可见劣化(第三张图);64 步的原始理由
   (细锥 8° 时远背景步长 1~3m 跨过近场细锥)在宽锥下不成立。**GLSL 已改、留在
   工作区未提交;LightTuneContract:195 仍钉 64,待用户体感拍板后改契约+提交**
   (嫌糙回退=把 composite1.fsh 的 32 改回 64+sync+reload)。
4. 表面照明(M1)只占 1.2ms,`!beamonly on` 不省帧;锥角每收窄都线性省
   (20°→8° 省 9.6ms)。若 32 步仍不够,下一步工程手段是"每 K 步做一次 DDA、
   步间复用透射率"(保采样密度、DDA ÷K),未立项待用户拍板。
5. 用户报的"240→40"与本表同量级(基线 fps 是视角强函数:同机同分辨率灯关
   看天 ~2100 / 看场景 128 / 本机位 354 都实测过——对比帧数必须同机位同视角)。
