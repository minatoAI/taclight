# 2026-09-06 体积光遮挡查表化(方案二):in-pool 最坏场景帧数 38.4 → 65.4(+70%)

## 一句话

用户批的"方案二"落地:每帧 composite 一次性为每灯预计算**全向遮挡距离表**(shadow-map
思想的逐灯变体),composite1 体积光每采样从"384 格体素 DDA 行走"变为"1 次 texelFetch
查表"。在用户还原的最坏场景(主视角被体积光包围、近景亮墙+地面光池+远处光锥同屏,
4K)实测 **occl off(旧逐采样 DDA)38.4 帧 ≈ 用户早上体感的"掉到 40 帧";occl on
(查表)65.4 帧,+27 帧(+70%),帧时间 −10.7ms**;画面与旧路径等价(见下 imgdiff)。

## 设计(费曼版)

- 上午定位(见 2026-09-06-inpool-perf/ 与坑112):开灯掉帧的大头是 composite1 里
  **每个光池内像素 × 每步 × 每灯**的灯侧体素 DDA(64 步管线中 DDA 独占 20.6ms@4K)。
  DDA 的答案其实极冗余:同一盏灯,朝某个方向"最远能照多远(首个实心遮挡距离)"每帧
  只与方向有关,与屏幕像素无关。
- 于是把 DDA 从"逐采样"搬到了"逐灯逐方向":**composite 阶段(最早期、任何 DBG 早退
  之前)MRT 写 colortex8**,512×256 equirect 全向图,每 texel RGBA 打包 4 盏灯的
  "该方向首个遮挡距离 D"(D/128 归一,RGBA16 ≈2~4cm 量化;1.0=128m=该方向全通)。
- composite1 每采样:由 (采样点−灯位) 反算方向 → NEAREST 取一个 texel → 得 D →
  与采样距离比较得可见度 `clamp((D−dist)/FUZZ+0.5,0,1)`,与旧 DDA 的软化带语义一致。
- 遍历语义与 `taclight_vox_transmit` 完全镜像(起始格豁免 / tie 全轴推进 / 穿透软化
  TACLIGHT_VOX_FUZZ 0.35 / 树叶 ×0.40、植被 ×0.75 + 软地板 0.45),只是返回值从
  "透射率"改为"首个阻断距离"。树叶在表模式下保守偏暗(单层 0.4≤0.45 即触发),
  无漏光方向。
- 失效保护:体素栅格无效(无灯/禁用)时 Java 不置 flags bit4 → GLSL 自动回退旧
  逐采样 DDA,−1=可见的旧语义原样保留。
- interop:`TemplateLibrary.directiveFree`(坑80 fail-safe)已登记
  `TACLIGHT_OCCL_TABLE_AT` 钩子块,宿主包注入时替换为哨兵函数(全可见)。
