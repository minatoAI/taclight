## 数据实证(G 行 34 列,run-20260903-014100-287-p36452 = 修复前构建,用户测试实录)

- **根因 A = 模型俯仰约定反相**:s0010(全 fallback)livePitch=+8.44°(低头)
  时束向 pitch=+6.44°(**朝上**)——MC xRot 正=低头,首版按"正=抬头"+y=+sin(p)
  合成,低头→灯朝上、抬头→灯朝下,与用户症状①逐字吻合。
- **根因 B = 捕获束向反 180°**:s0005/s0006/s0007 的 hold 帧 dYaw=**179.98°**
  (100% 样本)——束骨 ±Z 拉伸符号未定,上传端 alignBeamAway 兜底保住画面,
  但 resolver 内部 capDir 反平行毒化 fresh/hold。
- **根因 C(症状②真凶) = lerp 穿零扫动**:dir=lerp(fallbackDir, capDir, weight),
  两端反平行时插值向量穿过零点,归一化后**单帧方向扫动 104.07°**(fresh 爬升段)
  ——入场 200ms 内光池扫半个圈,与"改之前差不多"一致(此缺陷两代构建同在,
  此前方向维度从无判定/契约覆盖,TP-CONTINUITY 只判 pos)。
- 修正一处历史误读:移动族俯仰拟合值 −6.0° 的物理语义是"枪口低于视线 6°"
  = MC xRot **正增量 +6°**(s0005 fresh 帧:livePitch=6.69°,捕获真值低头
  12.87°≈livePitch+6.18°)。上轮交付口径"−6°"叠加"抬头正"公式 = 双重反相。
