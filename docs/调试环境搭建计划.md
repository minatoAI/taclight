## 1. 旧项目方法考古与对比(本计划的直接依据)

旧项目 `mc-tarkov-like-shader-dev` 在 `qa/run-dev/t0-automation/` 已建成本机验证过的程序化调试链路:

| 旧资产 | 作用 | 移植决策 |
|---|---|---|
| `t0-drive.ps1` | 底层驱动:窗口查找/置顶/前台、**5 条按键注入通道**(SendKeys / keybd_event / SendInput 扫描码 / **PostMessage 后台消息通道** / 剪贴板粘贴)、`chat` 动作(T→输入→回车,可程序化执行游戏内命令)、GDI `CopyFromScreen` 窗口截图、pin/click/close/quit | **整体移植为本项目 `tools/drive.ps1`**(PS 5.1 兼容版,含已修的 PS5.1 扁平化与 null bug) |
| `t0-run-state.ps1` / `t0-c4-session.ps1` | 会话编排:preflight(无游戏窗口)→ 归档旧日志 → 启动前写 oculus.properties/options.txt → 后台启动 gradle(控制台重定向)→ **轮询日志 `logged in with entity id` 判就绪** → pin+聚焦 → 截图 → 关闭 → 收集日志/截图/摘要 | 模式照搬,作为 SOP-0 骨架 |
| `PatchDayTime.java` | 直接字节手术 level.dat(NBT)把 DayTime 置 13000,免进游戏设时间 | 保留为启动前兜底;日常用 chat 命令 `/time set` |
| `analyze-probe.ps1` | 截图像素级**色块簇检测**(红/绿/青/品红标记定位) | 移植,与 K 霓虹调试配套(程序化判定锥形,不靠肉眼) |
| `_grid_diff.ps1` | 双截图网格 RGB 差值 | 并入 tools,与 imgdiff 热图互补 |
| `style-metrics.ps1` | 风格量化指标 SAT/SHADOW/CONTRAST/TEMPAXIS(Rec.709 亮度域) | 移植,**M2 风格验收从肉眼升级为指标对比**(对标参考截图量化) |
| `test-pack.ps1` / `gen-manifest.ps1` | 无 GPU 静态契约测试(PASS/FAIL 权威字符串);证据包 SHA-256 manifest | 模式并入(本项目已有 checkShaderIncludes 等 gradle 守护,证据 manifest 采纳) |

**旧项目四条血泪结论(字节码/实测级,直接继承):**

1. **1.20.1 原版资源重载键 = F3+T,不存在 F3+R**(反汇编 `KeyboardHandler#handleDebugKeys`:key=84(T)→reloadResourcePacks,判定表无 82(R))。
2. **按键注入能送达"事件",置位不了"持键状态"**:三通道实测,F3 单击全部成功,但**组合键依赖 `InputConstants.isKeyDown(F3)` 的真实持键态,注入无法触发**。→ 所有自动化只用**单击键**与 chat 命令,禁止依赖组合键。
3. **1.20.1 `maxFps:0` = VSync 锁刷新率**(本机 120Hz),不是无限制。任何性能测量前 preflight 强制 options.txt `maxFps:260` + `enableVsync:false`。
4. **注入按键必须游戏窗口前台**(桌面单焦点);PostMessage 后台通道可发消息但持键态类操作不可靠。

**旧项目没走通、本计划补上的洞**:旧项目把 shader 重载判为"实时交互判据,必须真人按键"(他们按 F3+R 组合)。但 Oculus 1.8.0 存在独立键位 `key_iris.keybind.reload`(Reload Shaders,当前 unbound)——**把它绑定到单键(如 R)后,单击注入即触发重载,绕开组合键持键态问题**。P0 第一件事就是验证这条路(注入 R → 日志计数 `Reloading`),成则热重载全自动,败则退回 chat 命令/重选 UI/人工按键三兜底。

**通道层级(本次修订核心)**:
`tools/drive.ps1`(程序化,主)→ chat 命令(游戏内逻辑)→ computer-use(兜底,需要交互式 UI 时才用;会占用真实键鼠,尽量不用)。

## 3. 模块设计

### A. 布景 —— `/taclight scene <preset>`(服务端命令)

在固定场景区(**X=2000,Z=0,平台基面 Y=120**,远离出生点避免干扰)程序化搭建。
每条命令自带:清场(fill air + kill 非玩家实体)→ 搭建 → 锁环境
(`/time set midnight` + `doDaylightCycle false` + `doMobSpawning false` + `weather clear`)。
幂等:重复执行结果一致。

| preset | 布置 | 对应验收点 |
|---|---|---|
| `wall` | 东西向石砖墙 12×3×1(墙心过原点),墙后 2 格放 1 蜘蛛,墙前 2 格放 1 蜘蛛(对照) | SSO 遮挡切断、脚下无暗环 |
| `grass` | 草方块 16×16 台面 + 撒 30 株草/蕨/花 + 橡树、云杉各 1 棵 | 植被半透挡光、草地照明 |
| `corridor` | 封闭走廊 4 宽×3 高×24 长,深色混凝土壁(低反照率),无窗 | 体积光束、反平方衰减、软肩 |
| `bloom` | 黑暗小屋 6×5×4,一面开 2×2 门口,屋内机位朝门外看 | bloom 晕圈、错位复制 bug 复现位 |
| `duo` | 无建筑,手电+枪灯同开 | 多灯(lightCount=2)混合 |

实现:SceneBuilder 类(setblock/fill/summon 序列,约 300 行,注册进现有 TacLightCommand)。

### B. 机位 —— `/taclight cam <name|here|save>`

- `cam <name>`:把玩家精确传送到注册表中的 (pos, yaw, pitch) —— **同一 bug 的 A/B 对比必须同机位,传送=确定性,不依赖手稳**。
- `cam here`:打印当前机位(玩家可先手动找到好视角)。
- `cam save <name>`:把当前机位写入 `run/config/taclight-cams.json`(运行时注册表,免重新编译)。
- 内置初始机位与场景配套:`wall@front`、`corridor@end`、`bloom@inside`、`grass@low`。
- 传送后 `setDeltaMovement(0)` 防漂移;截图 SOP 里关视角摇摆。

### C. 控制通道 —— 三层(2026-08-29 P0 实测定型)

| 层 | 通道 | 用途 |
|---|---|---|
| 1(**主**) | **文件命令中继** `run/taclight-cmds.txt`(DebugCommandRelay,客户端 tick 2Hz 消费) | `/命令` 直发服务端;`!reload` 光影热重载;`!diag`;`!bench`。AI 写文件即完成一切游戏操作,零键鼠依赖 |
| 2(兜底) | `tools/drive.ps1`(移植 t0-drive:窗口锚定查找/置顶/click/shot/PostMessage 键) | 截图(`shot` 指定路径)、UI 按钮点击、窗口管理 |
| 3(最后) | computer-use | drive 链路失效时(经用户同意) |

drive.ps1 注意:窗口匹配已锚定 `^Minecraft`(宽匹配会误中聊天/终端窗口——已踩坑);
PostMessage 键注入只在前台态偶然可靠,**只用于 UI 点击与截图,不用于游戏按键**。

### D. 截图 —— 双通道 + 证据归档

- **主通道**:`drive.ps1 shot` → 指定路径 PNG(截图即落盘到我在命令里给的路径,免翻 screenshots 目录)。
- **次通道**:游戏原生 F2(`press F2`)→ `run/screenshots/`(校验用,或 drive 不可用时)。
- **computer-use**:最后兜底(远程会话等特殊场景),使用前先向用户打招呼。
- 证据归档:对比图进 `docs/evidence/<日期>-<主题>/`,命名 `<主题>-<机位>-<改动标签>.png`;重要证据包附 SHA-256 manifest(继承旧项目 gen-manifest 模式)。

| 改动类型 | 流程 | 耗时 |

### F. 状态取证 —— 调试键 + 结构化日志(继承旧项目 TACLIGHT_T0_* 模式)

在 ClientEvents 增加(键位选空闲键,P/O 优先):
- **P = diag dump**:一行结构化日志写 latest.log——`dumpLight0()` + binding7 + readReserved + 相机 pos/rot + L/K 状态 + 当前光影包名。QA 脚本 grep 汇总成 summary(旧项目 summary-*.txt 模式)。
- **O = bench**:按下后测 3 秒帧时间,输出 avg / 1% low / min FPS 到日志。
- **preflight 强制**(继承旧结论 3):任何测量会话先改 options.txt `maxFps:260` + `enableVsync:false`。
- 日志 grep 套路固定:`GlShader`(编译错)、`TacLight`(诊断)、`Iris`/`Reloading`(包状态)。

### G. 分析工具 —— `tools/`(PS/Node,零依赖)

- **`tools/imgdiff.js`**:两张同机位截图 → 差异热图 PNG(错位类 bug 修复前后一图定性)。
- **`tools/griddiff.ps1`**(移植 `_grid_diff.ps1`):指定网格坐标 RGB 数值对比(热图之外的精确读数)。
- **`tools/clusterprobe.ps1`**(移植 `analyze-probe.ps1` 色块簇检测):配合 K 霓虹调试,**程序化定位光锥几何**(簇心坐标/面积),锥形回归不靠肉眼。
- **`tools/stylemetrics.ps1`**(移植 `style-metrics.ps1`):SAT/SHADOW/CONTRAST/TEMPAXIS 四指标,**M2 风格验收用指标对标参考截图**。
- **shader 侧曝光锁定**:`TACLIGHT_EXPOSURE_LOCK` define(composite2 固定曝光)——自适应曝光会让 A/B 截图整体亮度漂移,锁掉后只剩目标变量。

## 4. 工作流 SOP

### SOP-0 会话骨架(移植 t0-run-state 模式)
```
preflight:drive find 确认无游戏窗口 → 归档旧 latest.log(单次运行日志唯一化)
→ options.txt 强制 260fps/关vsync → (Java 改动时)后台启动 runClient,重定向控制台
→ 轮询窗口 + 日志 'logged in with entity id' 判就绪(7 分钟超时)
→ drive pin + click 标题栏聚焦
```

### SOP-1 GLSL 视觉 bug(以当前 bloom 错位为例)
```
syncShaderPack → drive press R(热重载,轮询 Reloading 计数)
→ chat "/taclight scene bloom" → chat "/taclight cam bloom@inside"
→ 等 2s(曝光收敛)→ drive shot 指定路径 → 读 PNG
→ 不确定时切 DBG 视图重拍 → imgdiff/griddiff 对比修改前后 → 判定 → 改 → 循环
```

### SOP-2 遮挡类(SSO)
`scene wall` → `cam wall@front` → 常规图(光是否被墙切断)+ DBG 视图 2/3(系数与掩码)→ 判定。

### SOP-3 Java 改动
SOP-0 全程(含 QuickPlay 自动进存档)→ 等日志出现 ShaderPackDiag 自检 → 转入 SOP-1。

### 运行模式
- **AI 自驾(默认)**:我后台启动 runClient + drive.ps1 全程程序化操作。窗口置顶期间会遮挡用户桌面,**每次开跑前先向用户打招呼**;尽量压缩会话时长(旧项目单会话 ~5 分钟量级)。
- **用户伴飞**:用户自己开游戏玩,我改完 GLSL + 同步后请用户按一下 R。用于成品级验收。
- **computer-use**:仅当 drive.ps1 链路失效(如远程会话虚拟显示问题)时经用户同意使用。

## 6. 风险与坑位(P0 实战验证后全面修订)

1. **窗口匹配必须锚定 `^Minecraft`**(P0 新增,已修):宽匹配('Minecraft' 子串)会命中
   聊天/终端窗口(其标题常含对话内容),EnumWindows 取"最底层匹配"导致驱动目标随机漂移
   ——P0 一切"时灵时不灵"的总根源。截图/点击前先 `drive find` 确认返回的是游戏窗口。
2. **文件中继是唯一可靠的游戏控制通道**(P0 定论):键注入(物理 keybd_event/SendKeys/
   PostMessage)受焦点态影响不可复现(T 一次成功后全部失效)。一律写 `run/taclight-cmds.txt`。
3. **客户端命令树"为空"是 P0 误判**(v2.2 翻案):P1 在 DIAG 增加 cmdtree 取证后,同条件
   (QuickPlay,dev 实例)实测 `cmdtree 72 taclight=true` —— 树健康且 /taclight 在树里。
   P0 所见"打字全被预览拒绝"另有原因(嫌疑:登录早期窗口期打字/P0 观察方式),待真人复测;
   不阻塞任何工具链功能(中继直达服务端)。
4. **MSYS 路径转换**(P0 踩坑):Git Bash 下以 `/` 开头的参数会被改写成 Git 安装路径
   (`/taclight` → `...Git/taclight`),所有 drive.ps1 调用必须加 `MSYS_NO_PATHCONV=1`。
5. **PS 5.1 读无 BOM 的 UTF-8 会按 ANSI 解析**,中文字符串被截断导致语法错——所有含中文的
   .ps1 必须带 BOM;多行 hashtable 字面量也会解析失败(保持扁平化);改后跑 parse-check ERRCOUNT=0。
   另外 PS5.1 `Set-Content -Encoding UTF8` 写出带 BOM,写 options.txt 等游戏配置要用 ASCII。
6. **组合键注入不可行**(旧结论 2,维持):单击键+命令;不要回头尝试 F3+X 类注入。
7. **maxFps:0 陷阱**(旧结论 3,维持):FPS 测量前 preflight 强改 options.txt(P0 实测未走
   preflight 时 BENCH 被锁 118.7≈VSync120);session.ps1 已内置。
8. **SP 自动暂停**(P0 观察):游戏窗口失焦会弹暂停菜单吞键——文件中继天然免疫;drive UI 点击
   前先截图确认当前屏幕状态。
9. runClient 是 dev 启动(与发布 jar 环境有差异),成品级验收仍走发布产物 + 用户实机。
10. 场景区固定 X=2000,不污染玩家存档区;存档 `test` 专用于调试(Cheats 已开),PROBE 保留。
11. P/N/B/J 键位已实测无冲突(R/P/O 被 TaCZ/原版占用);键位供真人使用,自动化走中继。
12. **session.ps1 调用禁止管道**(P1 踩坑,代价 25 分钟):`powershell … session.ps1 | tail` 会
    永久挂起 —— Start-Process 启动的游戏进程树继承 stdout 管道写句柄,tail 等 EOF 要等到游戏退出
    (session.ps1 本体 20:19:01 就 READY 结束了)。**一律文件重定向**:`> tools/.session/launch.log 2>&1`
    然后轮询该文件;文件句柄被继承无害。
13. **mc.reloadResourcePacks() ≠ 光影重载**(P1 实锤,证伪 P0):资源重载计数照涨、日志无错,
    但 Oculus 1.8.0 的 `Creating pipeline` 一次都不出现 —— 包文件改了也不生效(曾导致整轮 DBG
    视图"看似失效")。真重载 = Iris 自己的重载键绑入口 **Iris.reload()**(公开静态方法;
