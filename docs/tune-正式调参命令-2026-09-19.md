# /taclight tune 正式调参命令(2026-09-19)

八旋钮(`bright/dist/atten/knee/beam/scat/beamcap/cone`) + `voxel`(2026-10-06 再加 `held`,共十旋钮)
由文件命令中继
(`!bright`…/`!voxel`,dev/调试构建专用,发布包被 `build.gradle` 剔除)晋升为正式服务端命令,
发布包可用。调参**本机即时生效 + 写回 `config/taclight-client.toml` 重启保留**。

## 用法

```
# 第 1 层:概览(它是什么 + 一条真能用的示例 + 下一步去哪)
/taclight tune                                    # 同 tune help
/taclight tune help

# 第 2 层:索引(有哪些可调;一行一个短标签)
/taclight tune list

# 第 3 层:单项展开(范围/默认/当前值 + 调大调小 + 讲解 + 用法)
/taclight tune <name> help                        # 也可写 /taclight tune help <name>

# 看数(不改状态)
/taclight tune status                             # 全部当前值(四项表)
/taclight tune <name>                             # 单项当前值(同 <name> status)

# 调参
/taclight tune <name> <值>                        # 即时生效 + 写 toml
/taclight tune <name> clear                       # 清除覆盖、回默认值 + 写回 toml(voxel 除外,见下)
/taclight tune voxel <on|off>                     # 体素开关(字面语义)
/taclight tune held <0..15>                       # 手持光照值(氛围底光;整数,0=关)
```

## 三层入口(2026-10-06 用户定案:命令调节"有点杂乱",分层)

按**上手顺序**分三层,每层只干一件事(层与层的文案不重复 —— 索引不给数值,status 不讲原理):

```
$ /taclight tune
[TacLight] tune —— 边看边调手电/枪灯的光效(即时生效,并写回 config/taclight-client.toml 重启保留)
  直接能用的一条: /taclight tune bright 12      把亮度调到 12(敲下去立刻变,聊天栏回执)
  有哪些可调:     /taclight tune list
  某一项怎么用:   /taclight tune <名> help       例: /taclight tune cone help
  看当前值:       /taclight tune status(全部)| /taclight tune <名>(单项)
  还原某一项:     /taclight tune <名> clear
  注: voxel 是字面开关 on/off(回默认请 on);调参只对单人/主机的本机生效。

$ /taclight tune list
[TacLight] tune 可调项(10):
  bright   亮度
  dist     照距
  atten    衰减(尾巴长短)
  knee     近场软肩(贴脸过曝)
  beam     体积光柱浓淡
  scat     光柱轴向底亮
  beamcap  多灯重叠上限
  cone     光锥宽窄
  voxel    体素遮挡开关
  held     手持光照值(氛围底光)
  看某一项的用法与范围: /taclight tune <名> help     例: /taclight tune cone help
  看当前值(全部):       /taclight tune status

$ /taclight tune cone help
[TacLight] tune cone help
  cone —— 光锥宽窄
  范围 2..45   默认 8/4   当前 外8/内4(未覆盖)
  调大=光锥更宽(散);调小=更窄(更接近平行光)
  说明: 一写二:设外锥 v 会把内锥一起写成 v×0.5(内锥=全亮核心)。8/4 是"接近平行光"档。
  用法: /taclight tune cone <值> | /taclight tune cone status | /taclight tune cone clear
```

三层的数据源都在 `TuneKnobs`(每个旋钮三条文案:`label` 索引短标签 / `hint` 调大调小 / `note` help 讲解),
契约要求三条都非空、label ≤12 字、note ≥10 字 —— 加旋钮时不许只写个名字。

保留字 `list` / `status` / `help` / `?` 不可作旋钮名(契约钉死):撞了的话分层入口会被旋钮吃掉。

`help` / `list` 是**静态文案,零客户端引用**,故它们在 MP 守卫**之前**返回 —— 专用服上
"看命令怎么用"是正当需求,不该被"仅单人/客户端生效"挡掉;而 `status` / `<名>` / `<名> help`
要读本机覆盖层与体素门,仍走守卫。

`name` 大小写不敏感。数值含小数点(`0.35`/`-0.1`),命令参数用 `string()` 解析
(`word()` 拒收 `.`,与 `cam save` 的 `@` 教训同类)。

`clear` 是"清除覆盖、回默认值"的**正名**(2026-10-06 起;旧写法 `off` 仍接受,是兼容别名,
不再出现在任何用法/回显文案里)。`status` 每项回显**四项**:
当前值 → 范围 → 默认值 → 调大/调小说明:

```
[TacLight] tune status(改过的项已写 toml,重启保留):
  bright  = 6.0(未覆盖)   范围 0.5..30   默认 6.0   调大=更亮、照得更远;调小=更暗、照得更近
  atten   = 8.0(已覆盖)   范围 0.2..20   默认 20.0   调大=衰减更快、远处更暗(尾巴更短);调小=衰减更慢、远处更亮(尾巴更长)
  cone    = 外12.0/内6.0(已覆盖)   范围 2..45   默认 8/4   调大=光锥更宽(散);调小=更窄(更接近平行光)
  voxel   = on   范围 on/off   默认 on   开=方块遮挡生效(推荐);关=回退SSO老路径(慢速对照,仅调试)
  held    = 10(未覆盖)   范围 0..15   默认 10   调大=周围氛围光更亮(接近火把);调小=更暗(0=只留锥形光,不影响锥形主光)
清除某项覆盖(回默认并写回 toml): /taclight tune <名> clear   |   例: /taclight tune cone 12
```

单旋钮查询(`/taclight tune cone status`)第一行同样凑齐前四项,第二行给调大/调小,第三行给清除指路;
`voxel` 的单旋钮查询会附完整网格诊断(`box=… builds=… lastBuildMs=…`),列表里只给 `on/off`
(网格诊断对调参是噪音)。

## 映射表(命令名 → 覆盖层函数 → config 键 → 范围 → 默认值)

`label`(索引里的短标签)也在这张表的语境里;`note`(help 讲解)逐旋钮见
`TuneKnobs` 注册表(唯一真源,此处不复制)。

| 命令名 | 覆盖层函数(即时生效) | toml 键(`[spotlight]`) | 范围 | 默认值 | clear 语义 |
|---|---|---|---|---|---|
| bright | `LightTuneOverride.configureBright` → `brightnessFor` | `intensity` | 0.5..30 | 6.0 | 回 6.0 并写回 |
| dist | `configureDist` → `radiusFor` | `radius` | 4..96 | 36.0 | 回 36.0 并写回 |
| atten | `configureAtten` → `attenK` (SSBO cone.z) | `attenK`(**新增**) | 0.2..20 | 20.0 | 回 20.0 并写回 |
| knee | `configureKnee` → `kneeG` (SSBO cone.w) | `kneeGain`(**新增**) | 0.2..8 | 2.0(默认即开) | 回 2.0 并写回 |
| beam | `configureBeam` → `beamDensityOr` (vlParams.y) | `beamDensity` | 0..1 | 0.25 | 回 0.25 并写回 |
| scat | `configureScat` → `scatOr` (vlParams.x) | `scatFloor`(**新增**) | 0..0.9 | 0.04 | 回 0.04 并写回 |
| beamcap | `configureBeamcap` → `beamCapM` (vlParams.z) | `beamCapM`(**新增**) | 0.25..8 | 1.0 | 回 1.0 并写回 |
| cone | `configureCone` → `coneDeg` (直改 cos) | `coneOuterDeg`+`coneInnerDeg`(一写二,inner=outer×0.5) | 2..45 | 8/4 | 回 8/4 并写回 |
| voxel | `VoxelGrid.configure` | `voxelEnabled`(**新增**,布尔) | on/off | on | **off=字面禁用并持久化**(不对称;回默认请 `on`) |
| held | `LightTuneOverride.configureHeld` → `heldLevel()` | `heldLightLevel`(**新增**,**整数**) | 0..15 | 10 | 回 10 并写回 |

消费点(均在 `ClientSpotlightUploader.buildSpotBeam`,未动):
`brightnessFor`→intensity、`radiusFor`→radius、`coneDeg`→cosOuter/cosInner、
`beamDensityOr(p.beamDensity)`→density、`attenK`→cone.z、`kneeG`→cone.w、
`scatOr`→sideFloor、`beamCapM`→beam。`VoxelGrid.update` 每渲染帧消费开关。

范围与 `LightTuneOverride` 同源(覆盖层改范围必须同步改 `TuneKnobs`,契约双向对账);
默认值 = 各路未覆盖(clear 态)时的当前有效值。注意 `atten` 默认是 **20.0**(2026-09-06 扫参冻结,
`TACLIGHT_ATTEN_K=20.0`),旧文案/注释里的 "5.0" 已同步修正(行为未动,off 仍是哨兵 0)。

## MP(多人)行为

- **专用服**:命令命中即回显如下,原文:
  `[TacLight] tune 仅单人/客户端生效:专用服务器无本地调参目标…本次未应用。`
  返回 0,**不碰**覆盖层/config/体素(后者含 client 引用,专用服加载即炸,守卫在任何调参引用之前)。
- **单人/集成服**:同 JVM,直接调覆盖层 + `VoxelGrid` 即时生效 + 本机 toml 落盘。
- **LAN**:远端客机的命令发到**主机**执行,生效的是主机本机;回显明确作用域,不静默假成功。
  客机要调自己请在自己机器执行。真正的跨端同步(发包通道/客户端命令)未做,有需要另立项。

## 真持久 vs 内存态

- **十旋钮全真持久**(上表)。机制:覆盖层(即时) + toml(重启)双写;`clear` 把 config 键
  **写回默认值**(否则"清除后仍是上次值"=静默假成功);`status`/无参/`help` 零写盘(含 `save` 也不调)。
- **仍内存态(未晋升,故意的)**:`beamonly`/`occl`/`tm` 留在文件命令中继——
  `beamonly` 是调试观察位(关表面照明,放进正式命令会被当"灯坏了");
  `occl`/`tm` 是性能 A/B 开关(默认开,off=慢速对照,持久化会把"慢"带过重启)。
  `!lv` 旧档位被 `bright` 取代,同样不晋升。
- 开机恢复(`ClientEvents` 首世界 tick 一次性):只回填**新增键的非默认值**;
  既有键消费者直读 config 无需回填;默认值=未覆盖态(回填与否效果一致,不回填则 status 保持诚实的"未覆盖")。
- 中继与 tune **后写者胜**(同一覆盖层);中继保持纯内存重启清零不变,要持久化请走 tune。

## 越界与日志

越界/非法一律拒绝 + 不污染当前值 + 不写盘,回显形如

## held:手持光照值(heldBlockLightValue,2026-10-06 新增)

**它是什么**(用户问"是不是有个类似火把的亮度值"):是,但**不是原版方块光**。

| 层 | 名字 |
|---|---|
| 光影 uniform | `heldBlockLightValue` / `heldBlockLightValue2`(配套 `heldBlockLightColor`、`heldItemId`)—— OptiFine 时代术语,OptiFine/Iris 着色器规范里的"手持方块光值" |
| Iris 给模组的接口 | `IrisItemLightProvider.getLightEmission`(`net.irisshaders.iris.api.v0.item`),模组在 `FlashlightItemIris` 与 `GunItemLightProviderMixin` 实现 |
| Oculus 里的消费点 | `IdMapUniforms$HeldItemSupplier`(把值填进上面那几个 uniform) |
| 光影包里的选项名 | **Dynamic Handheld Lighting** —— Complementary 的 `HELD_LIGHTING_MODE`(0=OFF/1=Subtle/2=Normal,`common.glsl` 默认 `2`),lang 原文 "Allows handheld light sources to cast light onto the scene." |

取值是**方块光等级量纲 0..15**(火把 14、萤石 15);包那边也完全按方块光用它
(`heldLighting.glsl` 连岩浆桶都硬编码 `heldLight = 15`,并有 `if (heldLight > 15.1) heldLight = 0.0;`)。

**与"动态光源(Dynamic Lights)"的区别**(容易混,作用域不同):

| | Dynamic Lights(动态光源模组) | held block light(本旋钮) |
|---|---|---|
| 干什么 | 把发光物品注入**原版光照引擎** | 只往**光影管线的 uniform** 填一个数 |
| 世界方块光 | 真的变(周围方块被点亮) | **不变** |
| 别人看得见吗 | 看得见(世界状态) | 看不见,纯本机渲染 |
| F3 光照等级 | 会变(有的实现连刷怪都影响) | 不动 |
| 消费方 | 原版光照引擎 | 光影包(`heldLighting.glsl` 的暖氛围光) |

模组里**一行世界光照写入都没有**(全仓无 `LightLayer.BLOCK`/光照引擎调用)。大类上它属于
"动态光源"家族(OptiFine 时代就叫 Dynamic Handheld Light),严格说是**着色器统一值**。

**两条边界**(写进旋钮说明,免得当成"旋钮坏了"):

1. **它不影响锥形主光**。锥形光走 SSBO 通道(`bright/dist/cone/atten/…`),改 `held` 锥形光一点不变;
   `held` 只管玩家周围那圈暖氛围底光。
2. **它只在光影包开着 Dynamic Handheld Lighting 时可见**。Complementary 默认 Normal(=开);
   用户自己在光影设置里设成 OFF 的话,调多少都看不出来。

**默认 10 的单一真源**:`LightTuneOverride.DEFAULT_HELD_LEVEL = 10`(2026-09-04 用户体感定案:
15 像火把太强、5 基本看不见、10 折中)。此前这个 10 在 `FlashlightItemIris` 与 `GunControl` 各写一份,
现在两处都改成调 `heldLevel()`。

**整数键**:`heldLightLevel` 是 Forge `ConfigValue<Integer>`,`Sink.setDouble` 会炸 ⇒ 持久化层
新增 `setInt/getInt` 一路,由 `TuneKnobs.Kind.INT` 路由(`isIntKey` 按 config 键判定)。
小数(`12.5`)一律**拒绝**而不是静默取整(取整会变成"回显 12 但你填的是 12.5"的假成功)。

## 用词与文案改造(2026-10-06,用户反馈)

**用户原话**:"截图里面写的这个 OFF 是看得有点懵逼啊,就相当于是默认值嘛……这写个 OFF 是啥意思?
意思就是说我写 OFF 它就是默认值,是这个意思吗?那你不如把它改成 clear……然后每一项后面的这个括号
里面说明都没什么意义,改一下,改成说明这个参数调大了会怎么样,调小了会怎么样。"

**问题定性**(不是文案瑕疵,是设计缺陷):`off` 一个词承担了两种语义 ——
数值旋钮的"清除覆盖、回默认值",和 `voxel` 的"字面禁用"。而且状态回显 `off(默认 intensity=6.0)`
长得**像一个可以填的值**,用户自然会问"我填 off 就是默认值吗"。答案恰好是"是(数值旋钮)"、
"不是(voxel,填 off 是禁用遮挡)" —— 一个词两种答案,必须拆。

**改法**:

| 项 | 改前 | 改后 |
|---|---|---|
| 数值旋钮清除覆盖 | `tune bright off` | `tune bright clear`(`off` 仍接受,兼容别名) |
| 状态回显 | `off(默认 intensity=6.0)` | `6.0(未覆盖)` / `12.0(已覆盖)` |
| 每项字段 | 只有"值 + 重复键名/范围" | **四项齐全**:当前值 → 范围 → 默认值 → 调大/调小说明 |
| voxel | `off` 与数值旋钮的 `off` 同形 | 保留 `on/off` 字面开关,`clear` **明确拒绝**并指路 `on` |

**第二轮补充(同日,用户要求)**:括号说明里**也要带范围**,并且每项固定四项
(当前值 / 范围 / 默认值 / 调大调小)—— 默认值因此从覆盖层状态串
(`6.0(未覆盖,config 默认)`)里**移出**,改由 `TuneKnobs.clearTo()` 作为独立字段给出
(两处各写一份就是漂移源);覆盖层状态串只留 `(未覆盖)`/`(已覆盖)`。
