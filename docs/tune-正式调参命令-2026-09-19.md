# /taclight tune 正式调参命令(2026-09-19)

八旋钮(`bright/dist/atten/knee/beam/scat/beamcap/cone`) + `voxel` 由文件命令中继
(`!bright`…/`!voxel`,dev/调试构建专用,发布包被 `build.gradle` 剔除)晋升为正式服务端命令,
发布包可用。调参**本机即时生效 + 写回 `config/taclight-client.toml` 重启保留**。

## 用法

```
/taclight tune                                    # 九旋钮全状态 + 用法(只读)
/taclight tune <name>                             # 单旋钮 status(只读)
/taclight tune <name> status                      # 同上
/taclight tune <name> <值>                        # 调参:即时生效 + 写 toml
/taclight tune <name> off                         # 回默认 + 写回 toml(voxel 除外,见下)
/taclight tune voxel <on|off>                     # 体素开关(字面语义)
```

`name` 大小写不敏感。数值含小数点(`0.35`/`-0.1`),命令参数用 `string()` 解析
(`word()` 拒收 `.`,与 `cam save` 的 `@` 教训同类)。

## 映射表(命令名 → 覆盖层函数 → config 键 → 范围 → 默认值)

| 命令名 | 覆盖层函数(即时生效) | toml 键(`[spotlight]`) | 范围 | 默认值 | off 语义 |
|---|---|---|---|---|---|
| bright | `LightTuneOverride.configureBright` → `brightnessFor` | `intensity` | 0.5..30 | 6.0 | 回 6.0 并写回 |
| dist | `configureDist` → `radiusFor` | `radius` | 4..96 | 36.0 | 回 36.0 并写回 |
| atten | `configureAtten` → `attenK` (SSBO cone.z) | `attenK`(**新增**) | 0.2..20 | 20.0 | 回 20.0 并写回 |
| knee | `configureKnee` → `kneeG` (SSBO cone.w) | `kneeGain`(**新增**) | 0.2..8 | 2.0(默认即开) | 回 2.0 并写回 |
| beam | `configureBeam` → `beamDensityOr` (vlParams.y) | `beamDensity` | 0..1 | 0.25 | 回 0.25 并写回 |
| scat | `configureScat` → `scatOr` (vlParams.x) | `scatFloor`(**新增**) | 0..0.9 | 0.04 | 回 0.04 并写回 |
| beamcap | `configureBeamcap` → `beamCapM` (vlParams.z) | `beamCapM`(**新增**) | 0.25..8 | 1.0 | 回 1.0 并写回 |
| cone | `configureCone` → `coneDeg` (直改 cos) | `coneOuterDeg`+`coneInnerDeg`(一写二,inner=outer×0.5) | 2..45 | 8/4 | 回 8/4 并写回 |
| voxel | `VoxelGrid.configure` | `voxelEnabled`(**新增**,布尔) | on/off | on | **off=字面禁用并持久化**(不对称;回默认请 `on`) |

消费点(均在 `ClientSpotlightUploader.buildSpotBeam`,未动):
`brightnessFor`→intensity、`radiusFor`→radius、`coneDeg`→cosOuter/cosInner、
`beamDensityOr(p.beamDensity)`→density、`attenK`→cone.z、`kneeG`→cone.w、
`scatOr`→sideFloor、`beamCapM`→beam。`VoxelGrid.update` 每渲染帧消费开关。

范围与 `LightTuneOverride` 同源(覆盖层改范围必须同步改 `TuneKnobs`,契约双向对账);
默认值 = 各路 off 时的当前有效值。注意 `atten` 默认是 **20.0**(2026-09-06 扫参冻结,
`TACLIGHT_ATTEN_K=20.0`),旧文案/注释里的 "5.0" 已同步修正(行为未动,off 仍是哨兵 0)。

## MP(多人)行为

- **专用服**:命令命中即回显如下,原文:
  `[TacLight] tune 仅单人/客户端生效:专用服务器无本地调参目标…本次未应用。`
  返回 0,**不碰**覆盖层/config/体素(后者含 client 引用,专用服加载即炸,守卫在任何调参引用之前)。
- **单人/集成服**:同 JVM,直接调覆盖层 + `VoxelGrid` 即时生效 + 本机 toml 落盘。
- **LAN**:远端客机的命令发到**主机**执行,生效的是主机本机;回显明确作用域,不静默假成功。
  客机要调自己请在自己机器执行。真正的跨端同步(发包通道/客户端命令)未做,有需要另立项。

## 真持久 vs 内存态

- **九旋钮全真持久**(上表)。机制:覆盖层(即时) + toml(重启)双写;`off` 把 config 键
  **写回默认值**(否则"off 后仍是上次值"=静默假成功);`status`/无参/`help` 零写盘(含 `save` 也不调)。
- **仍内存态(未晋升,故意的)**:`beamonly`/`occl`/`tm` 留在文件命令中继——
  `beamonly` 是调试观察位(关表面照明,放进正式命令会被当"灯坏了");
  `occl`/`tm` 是性能 A/B 开关(默认开,off=慢速对照,持久化会把"慢"带过重启)。
  `!lv` 旧档位被 `bright` 取代,同样不晋升。
- 开机恢复(`ClientEvents` 首世界 tick 一次性):只回填**新增键的非默认值**;
  既有键消费者直读 config 无需回填;默认值=off 态(回填与否效果一致,不回填则 status 保持诚实的 off)。
- 中继与 tune **后写者胜**(同一覆盖层);中继保持纯内存重启清零不变,要持久化请走 tune。

## 越界与日志

越界/非法一律拒绝 + 不污染当前值 + 不写盘,回显形如
`[TacLight] tune bright 拒绝 '99': range 0.5..30, got 99 (范围 0.5..30,或 status/off)`,
同时 `LOGGER.warn("[TacLight] TUNE reject ...")`;成功记 `info("[TacLight] TUNE ...")`。
全状态无参 Opp 走 `info`。自动化 grep 依赖 `[TacLight]` 前缀(与既有命令同规)。

## config 兼容性

- 新增 5 键带默认值,存量 toml 自动补齐;`coneOuterDeg` 下限 5.0→2.0、`coneInnerDeg` 下限
  2.0→1.0(**只放宽不收紧**,存量值全兼容;tune cone 2..5 否则写不进 toml)。
- `SPEC.save()` 落盘:本仓此前零先例(全仓 grep 无 `set`/`save` 调用),生产 `Sink` 已包
  `try/catch`,失败回显"覆盖层已生效,但 toml 写入失败:…——重启不保留!",不静默假成功。
