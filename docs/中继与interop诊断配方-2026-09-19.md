# 中继通道与 `!interop` 诊断配方(2026-09-19)

> 起因:qa 在独立实例里写 `run\taclight-cmds.txt` 后**零 RELAY 行**,一度被误读成"注入修复回归"。
> 实测定性:**诊断工具链缺口**,与注入无关。本页把路径口径、发布包边界、配方与验收一次写清。

## 1. 路径口径(最常踩)

| 项 | 事实 |
|---|---|
| 监听路径 | **`<gameDir>/taclight-cmds.txt`**(`DebugCommandRelay.java` 的 `FMLPaths.GAMEDIR.get().resolve("taclight-cmds.txt")`) |
| **不是** | `<gameDir>/run/taclight-cmds.txt` —— 旧 javadoc 写"run/taclight-cmds.txt"**只在 dev 实例成立** |
| dev 实例 gameDir | `E:\dshHome\mc-mod-spotlight-attachment\taclight\run` ⇒ dev 写 `run\taclight-cmds.txt` **正确** |
| 独立实例 gameDir | 实例根(例:`E:\dshHome\qa9-m1-smoke\game-full`)⇒ 必须写 **`game-full\taclight-cmds.txt`** |
| 判定 gameDir 的办法 | `<gameDir>\logs\latest.log`、`<gameDir>\config\oculus.properties`、`<gameDir>\options.txt` 在哪一层;`<gameDir>\run\` 下若没有这些,`run/` 就只是普通子目录 |

## 2. 发布包边界(为什么发布实例里"零 RELAY 行"是预期)

`build.gradle` 的 `jar { ... }` 故意剔除调试通道:

```
exclude 'dev/taclight/debug/**'
exclude 'dev/taclight/mixin/debug/**'
exclude 'dev/taclight/client/DebugCommandRelay*.class'
exclude 'taclight.debug.mixins.json'
exclude 'taclight.dev.mixins.json'
```

⇒ **发布 jar 里不存在文件中继**(也不存在 `TicketBridge` 等 debug 类);`dev/taclight/interop/**`
是发布的(注入逻辑必须发布)。**用发布 jar 的实例里,写任何 `taclight-cmds.txt` 都不会有 RELAY 行**
——这是设计,不是故障。理由:该通道是"任何本地程序可写、写了即驱动客户端命令
(`!reload`/`!shot`/`!agent`…)"的**无守卫写入口**,与 modtest-mcp 的令牌+审计取向冲突。
将来若要开放:**只许放行只读子集**(如 `!interop`/`!diag` 的 status 查询)+ 另设开关/变体。

反回归断言:`InteropPackagingContract`(发布 jar 不含该类 / dev 构建树含该类 / exclude 规则在 /
路径表达式正确 / 文案不得再指"游戏内 !interop")。

## 3. 配方(逐字)

1. **用 dev 实例**(调试类在 classpath 上;发布包无此通道);
2. 进世界(**主菜单/无连接不消费**:`mc.getConnection() == null` 直接 return,文件保留);
3. **覆盖写** `<gameDir>/taclight-cmds.txt`:**UTF-8 无 BOM、一行 `!interop` + 换行**;
4. 等 **≥1 s**(轮询 2 Hz);
5. 期望日志(dev 实例 `run\logs\latest.log`):
   ```
   [TacLight] RELAY exec: !interop
   [TacLight] RELAY interop | interop 状态(最近一次解析):
   [TacLight] RELAY interop |   shaderPack(原始名) = "..."
   [TacLight] RELAY interop |   归一化匹配键      = "..."
   [TacLight] RELAY interop |   包根              = ...
   [TacLight] RELAY interop |   模板              = family=... packName=...
   [TacLight] RELAY interop |   通道              = known-good:anchors / best-effort:hash-drift / fast:name+hash
   [TacLight] RELAY interop |   逐文件结果        = <file>: 注入成功 +N chars  或  失败原因(算子/锚点)
   ```
6. **消费的可判定证据**:该文件被**截断为 0 字节**(读后写成空串,不删除)。

## 4. 验收判据

| 层 | 判据 |
|---|---|
| 离线(零真机) | `InteropStatusContract`(五要素+接线+生产接线守卫)、`InteropPackagingContract`(发布边界+路径+文案)全绿 |
| 真机 · dev 实例 | ≤2 s 内 `RELAY exec: !interop` + ≥5 行 `RELAY interop \| …` + 文件截断为 0 字节 |
| 真机 · 发布包实例 | **零 RELAY 行 = 预期**(不改打包就永远如此,不得记为失败) |

## 5. 相关事实(2026-09-19 实测)

- 发布 jar(`taclight-0.10.0.jar`,289006 B)内 `dev/taclight/client/` 18 个类,**无 `DebugCommandRelay`**;
  `dev/taclight/debug/**` **零条目**;`dev/taclight/interop/**` **在**(6 个类)。
- `build/classes/java/main/dev/taclight/client/DebugCommandRelay.class` **存在** ⇒ 是"被剔除"不是"没编译"。
- 独立实例 `game-full\taclight-cmds.txt` 里 09-17 的 3 条命令**从未被消费**(mtime/内容未变)= 该类不在包里的独立旁证。
- dev 实例 `taclight\run\taclight-cmds.txt` = 0 字节 = 该通道在 dev 里确实工作过。
- 文案坑:`RuntimePackInjector` 的聊天提示曾写"游戏内 `!interop` 看详情"——**不存在客户端命令路径**,
  把验收人都误导了;现改为"①日志搜 interop 看原因 ②dev 实例把 `!interop` 写入 `<gameDir>/taclight-cmds.txt`"。
