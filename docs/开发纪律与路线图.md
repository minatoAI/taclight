# 开发纪律与路线图

这个文档面向开发者和贡献者。产品介绍、安装与运行需求在根目录 `README.md`。

## 1. 技术栈

- Minecraft 1.20.1 / Forge 47.1.3 / Java 17
- 光影：Oculus 1.8.0（Iris 的 Forge 移植）+ Embeddium 0.3.31
- 已适配注入模板的光影包：Complementary Reimagined r5.9、iterationT 3.2.0
- 枪械联动：Timeless and Classics Zero 1.1.8-hotfix
- 数据通道：官方 Iris API（`IrisItemLightProvider`）给所有支持手持光的包兜底；自研 SSBO（`std430`，binding 7）加运行时注入给已适配的包提供"光从枪口出"、体积光与遮挡

## 2. 分支与仓库

远端只保留一条分支 **`main`**，它就是公开可见的仓库内容：

- **包含**：产品源码（含内部调试面 `debug` / `devonly`，这些包在打包时被剔除，不进发布件）、契约测试 `src/test`、工具链 `tools/`、开发文档 `docs/`、构建脚本、许可与致谢。
- **不包含**：第三方 jar（`libs/*.jar`，需要自行下载）、像素证据包 `docs/evidence/`（体积大且是历史存档）、一次性实验票据 `tickets/`。

本地开发分支叫 `master`，内容是 `main` 加上上面那三类大件。

发布流程就是把 `master` 的源码同步到 `main`：

```bash
git checkout main
git checkout master -- src pack tools docs build.gradle settings.gradle gradle.properties \
    gradlew gradlew.bat README.md RELEASE.md CHANGELOG.md THIRD_PARTY.md LICENSE .gitattributes .gitignore
git commit -m "release: <version>"
git push origin main
```

不保留一份手工改编的 `build.gradle`：公开分支与开发分支用**同一份构建脚本**，否则每次同步都要人工重新裁剪，那是纯维护税。历史教训是上一版的公开分支为了隐藏调试面而手改了 339 行 `build.gradle`，从此两边再也无法机械同步。

产品代码里不允许直接引用 `dev.taclight.debug.**` 或 `dev.taclight.devonly.**`：发布件会剔除这些包，生产代码直引它们会导致发布件在运行时缺类。构建脚本的剔除规则与契约里的构件闸门共同保证这条边界。

## 3. 开发命令

需要 JDK 17。可用环境变量 `TACLIGHT_JDK17` 指定 JDK 路径，或让 `gradlew-java17.cmd` 走它的默认查找。

```powershell
.\gradlew-java17.cmd build              # 编译 + 打包
.\gradlew-java17.cmd runClient          # 启动开发客户端
.\gradlew-java17.cmd taclightContracts  # 跑契约测试（见第 6 节）
.\gradlew-java17.cmd packShaderZip      # 打包自带光影包
.\gradlew-java17.cmd patchIterationT    # 生成 iterationT 的离线派生包（旧路线，运行时注入已覆盖）
```

离线构建：首次联网执行一次 `build` 之后，加 `--offline` 即可复用本地 Gradle 缓存。

依赖 jar 不进仓库（`libs/` 只有说明文件）。缺件时 `checkLocalDeps` 会明确报出缺哪个文件。

## 4. 开发纪律

1. **单一状态真源**：只维护一份状态清单，不并行维护多份互相矛盾的进度表。
2. **测试与脚手架独立 sourceSet**，主源码只放产品类。
3. **官方 API 优先**：反射与 mixin 收敛进 adapter 层，带版本探测，失败要 fail-closed。
4. **依赖全部 optional + 能力探测**，没有某个依赖时要降级，不能崩。
5. **GLSL 单源生成**，禁止手工双拷贝。注入到第三方包的 GLSL 由模板加内联 core 生成。
6. **许可红线**：本项目取 GPL-3.0-or-later。不重分发第三方 jar，不重分发改版光影包。Photon 禁止改版分发，HandheldMoon 为 ARR，只参考行为。
7. **新增数据通道要过检查表**：新增一个 SSBO binding 或新增一条前向渲染路径，必须同时改声明、前向精简路径的白名单、以及对应的构件断言。历史上这类改动漏掉一处会静默失效，表现为"代码写了但游戏里没生效"，很难从画面反推。
8. **每个阶段打 tag**，版本号以 `gradle.properties` 的 `mod_version` 为单一真源。

## 5. 当前状态

**0.11.2 预览版。** 已交付的能力：

- 手电筒物品，开关状态存在物品自己的数据里（切走再切回保持）。
- TaCZ 枪挂照明附件，逐枪独立开关，光从枪口出，跟随第三人称姿态。
- 体积光（丁达尔）、GGX 高光、色调链。
- 体素 DDA 遮挡：形状调色板最多 16 盒、高度感知、遮挡距离查表双线性、时间复用。
- 多人灯态同步：开关走实体同步数据，远程灯姿态由对端客户端重建，零新增网络包。
- 运行时注入：Complementary Reimagined r5.9 与 iterationT 3.2.0。
- 自带备用光影包，首次启动自动安装到 `shaderpacks/TacLight-Builtin`。
- 发布件已剥离全部调试面：只注册两个按键（手电、枪灯），无帧率基准、无诊断转储、无调试模式。

**已冻结：** 体素遮挡路线。复杂形状方块的像素级精度在这条路线上做不到，继续打磨只是收敛，不是消除。要消除需要把遮挡换成 GPU 每帧渲染的 shadow pass，属于换路线，不是调参。

## 6. 验证方式

- **契约测试**：`src/test/java/dev/taclight/**/*Contract.java`，无 JUnit 依赖的纯 JVM 断言，覆盖体素 DDA、上传器布局、姿态数学、配置解析、注入模板、发布件边界等。入口是 `AllContracts`。
  **已知缺陷：`taclightContracts` 目前是独立任务，没有接进 `build`。** 也就是说 `gradlew build` 不会跑它，绿不绿取决于有没有人显式运行。改动产品代码后请手动跑一次。
- **发布件构件闸门**：`InteropPackagingContract` 直接读发布 jar，检查 dev/调试面是否泄漏、版本号是否同源、以及已删调试类是否重新出现。
- **像素对照**：`tools/` 下有固定机位、场景预设与 `imgdiff` 工具，用于同机位同姿态的像素级 A/B。这部分是手工驱动的，还没有接成自动门禁。
- **证据包**：`docs/evidence/<日期>-<主题>/`，每个包含判定数字、原始数据与 `manifest.sha256`。

## 8. 踩坑记录

历史坑位按编号记在 `CHANGELOG.md` 与开发仓的坑位册里。接手时值得先看的几类：

- 光影注入的静默失效（改了主核但前向精简路径没跟上，画面无变化）。
- 环境性失败混进判据（权限错误、残留旧 jar、DPI 缩放、焦点抢占）。
- 工具链自身的坑（PowerShell 脚本编码、中继文件不得带 BOM）。
- 同一症状重复诊断：症状第二次出现时先冻结并写成结论，不要直接开新一轮调查。
