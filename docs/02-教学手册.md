# TacLight 教学手册(七轮实战复盘)

> 目标读者:想理解"模组如何给光影包喂真实光源"的人。按数据流顺序阅读。

## 1. 一句话架构
**模组负责"说"光源在哪、朝哪、多亮(SSBO);光影包负责"画"(注入 GLSL)。**
兼容性 = 数据通道的通用性:
- 通道 G(官方):IrisItemLightProvider → heldBlockLightValue → 任何手持光包都能亮(零改动);
- 通道 S(专属):binding 7 SSBO(std430,16B 头 + 96B/灯)→ 只有消费它的包(我们的派生包)能画。

## 2. 各层地图(文件 → 作用)
| 层 | 文件 | 一句话 |
|---|---|---|
| 物品 | item/FlashlightItem(+Iris 变体) | 物品变"光源",provider 读数 |
| 状态 | client/ClientLightState | 手电筒/枪灯两个独立开关(本地) |
| TaCZ | tacz/* | gunpack 注册(EXTRA_ENTRIES)+ 枪上 LASER 附件识别 |
| 姿态 | mixin/BeamRendererMixin + pose/MuzzlePoseMath | 从激光渲染矩阵抽出枪口姿态(视图空间) |
| 上传 | channel/ClientSpotlightUploader | 每 tick 打包 1-2 盏灯 → SSBO(binding 7) |
| 绘制 | shader_patches/taclight_lights.glsl(注入派生包) | 表面锥光/体积光束/高光/屏幕空间遮挡 |

## 3. 关键机理(各 3 分钟)
**SSBO 契约**:GLSL 与 Java 逐字节对齐(std430:vec4 16B 对齐)。改契约必须改三处:
SpotlightBufferLayout.java、taclight_lights.glsl、契约测试(读写回环)。→ 这就是"单源真源"纪律。

**坐标空间**(最容易错):
- ABI 存"场景相对坐标"(world - cameraPosition)——经过与相机无关、投影不变;
- iterationT 的光照函数用视图空间(viewPos);注入 GLSL 用 gbufferModelView 做切换;
- 光束/遮挡在视图空间做,world 端点在 shader 里用 cameraPosition/逆矩阵还原。

**遮挡模型**:屏幕空间 8 步深度遍历(保守边界:越界样本放行)。真投影阴影需要 Oculus
内部 shadowRenderTargets——两次旧项目验证为高风险,本项目的边界就画在这里。

**补丁管线**:锚点唯一性 + SHA-512 记录 + marker 幂等;原包零改动;用户本地生成派生包。
坑:a) JSON 转义(用 String.raw);b) insertAfter 必须带前导换行;c) #version 330→430。

## 4. 调试配方
- 光不亮:先问"通道通了吗"——日志看 gun light ON/OFF、muzzle capture armed;
  再看 Oculus 是否 Using shaderpack;最后确认 SSBO 上传无 warn。
- 光斑位置怪:看 MuzzlePoseCapture 是否 armed(枪口模式)还是回退(相机近似)。
- GLSL 报错:latest.log 找 Error compiling;改完跑 patcher 重新生成;F3+T 重载包。
- 数值发疯:检查 float 精度(Java 与 GLSL 同精度无所谓,但与 test 的 double 字面量有差)。

## 5. 独立实验建议
1. 把 cone 角改成 60°:config taclight-client.toml;体验探照灯;
2. 加一盏"副手灯"(ClientSpotlightUploader 里再 push 一个,副手时);
3. 用 Photon 跑一遍:item.properties 映射(路线 P)——对比不同包的"手电筒";
4. 把迭代T 内置 HELDLIGHT 关掉,只看我们的 SSBO 光(排除干扰);
5. 多人:2 台机子,看对方枪灯(目前不支持——这是 V5 的活)。
