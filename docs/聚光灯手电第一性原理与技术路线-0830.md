# 聚光灯手电的第一性原理与技术路线(2026-08-30)

> 回答三个问题:① 抛开 Minecraft,3D 游戏里的移动聚光手电在原理上由什么构成、怎么做对;
> ② 这些原理映射到 MC 模组/shader 光影包后,哪些可行、哪些被架构锁死;
> ③ 我们项目在原理坐标系里处于什么位置,问题到底出在哪。附带 Radiance / Caustica 查证结论。

---

## 1. 第一性原理:手电筒 = 渲染方程的四个子问题

一切光照渲染都在解渲染方程:

```
L_o(x, ω_o) = L_e(x, ω_o) + ∫ f_r(x, ω_i, ω_o) · L_i(x, ω_i) · (n·ω_i) dω_i   [表面]
            + ∫ σ_s(t) · phase(θ) · L_light · V(t) dt                          [介质]
```

"玩家手中的可移动聚光手电"不是新东西,它是把这四个子问题各解一遍:

### 子问题 1:锥形直接光(漫反射)
```
L = albedo × cone(cos_inner..cos_outer, θ) × atten(r) × max(0, n·l)
```
- **数据需求**:光源位置/方向(每帧变)、表面法线、光强。
- **难度:一行代码**。任何框架(前向、deferred、光影包 composite)一个 pass 搞定。
- 这是所有人以为"聚光灯"的全部。它只是 1/4。

### 子问题 2:镜面高光(specular)
- f_r 换成 GGX(N·H, roughness, F0)。手电照在金属枪身上那道会变形的亮斑就是它。
- **数据需求**:材质粗糙度/F0 —— 必须有材质系统(GBuffer/PBR 参数)。
- **难度:中等**。公式不难,难在"材质参数从哪来"。
- **视觉意义:高光斑是"聚光"感的重要来源**——只有漫反射的聚光灯,照在光滑表面上没有那道随锥形拉伸变形的亮斑,观感"糊"。

### 子问题 3:遮挡 / 阴影(可见性 V)
```
V(x, light) = 光线 x→light 是否被场景截断
```
- **这是唯一昂贵且唯一无法缓存的项。** 原因:光源每帧移动,任何针对光源的遮挡数据(阴影贴图)都活不过一帧,必须每帧重建。
- **难度:架构级**。整个"手电筒为什么难"的问题,90% 就是这一项。

### 子问题 4:体积光束(volumetric beam)
```
inscattering = ∫ σ_s(t) · phase(cosθ) · atten(t) · V(t) dt     [沿视线 raymarch]
```
- **数据需求**:介质密度、相位函数(HG)、以及**每个 march 步的可见性 V —— 又回到子问题 3**。
- 所以体积光束的精度上限被遮挡方案锁死:没有阴影正解,体积光束的"被墙截断"也只能是近似。

### 核心洞察

> **子问题 1/2/4 是算术,子问题 3 是架构。**
> 锥形衰减公式网上随处可见且全对;让手电"看起来正确"的是阴影,而阴影贵在"每帧移动的光源使一切缓存失效"。

## 2. 子问题 3 的历史,就是手电筒的历史

| 年代 | 方案 | 代表 | 代价 |
|---|---|---|---|
| 2004 | Stencil shadow volume(每光源 CPU 重投影场景几何) | **Doom 3**、F.E.A.R. | 几何处理重,光源数受限;第一次让"手电+精确阴影"成立 |
| 2007+ | **Spot shadow map**(光源视角渲一张 2D 深度图,采样比较 + PCF) | Metro、Resident Evil、Alien: Isolation | spot 光只需 1 张深度图(视锥即锥体,比点光源 cube map 便宜 6 倍),每帧重渲 512×512 完全可承受 —— **AAA 手电的标准答案** |
| 2010s | Deferred light pass(手电 = GBuffer 上一个全屏 pass 循环光源) | GTA5、现代标配 | 依赖 GBuffer 框架 |
| 2018+ | 硬件 RT shadow ray(每像素一条 shadow ray) | Metro Exodus EE、Control | 需 RTX;完美但有噪点,靠降噪 |

**共同点:光源动 → 阴影每帧重建。没有别的路。** 同时注意:RT 并不是手电的必要条件——Metro/RE 系在传统管线里早就把手电做对了。**做对 ≠ 必须 RT。**

## 3. 映射到 Minecraft:哪些被架构锁死

### 3.1 vanilla 光照体系与"移动光源"根本相克

Minecraft 的光照是一张**预烘焙的体素亮度表**:block light 0–15 存进 chunk,方块更新才重算,不含方向、不含遮挡方向。它是"入射光强的空间积分",不是"光源"。

由此推出 DynamicLightsReforged 家族(LambDynamicLights 谱系)的原理天花板:
- 它把动态光亮度**注入 lightmap 坐标**(方块光 nibble × 16 子级);
- 注入的那一刻,方向信息就丢了——lightmap 是标量场,读出来只有"这里多亮";
- 所以这条路线**原理上做不出聚光灯形状**。HandheldMoon 在其上叠的"角度遮罩"是体素粒度的补丁(每个方块按角度衰减),注定是方块锯齿。

### 3.2 Iris/Oculus composite = 屏幕空间 deferred 框架(子问题 1/2/4 的原生家)

光影包的管线结构与 AAA deferred 渲染同构:
- `gbuffers_*` 写 GBuffer(colortex0=颜色, colortex1=法线/材质, colortex2/3=各类辅助)≡ AAA 的 GBuffer pass;
- `composite*` 全屏 pass 读 GBuffer ≡ **light pass**;
- 手电 = composite 里读 SSBO 光位做 N·L —— 我们项目的 M1 就是这个,这不是巧合,是架构上的正确选择。

### 3.3 子问题 3 在 Iris 里的全部选项(为什么别扭的根源)

| 选项 | 判定 |
|---|---|
| Iris shadow pass(阴影贴图) | **被锁死**:每帧只跑一次、方向绑定太阳/月亮(Iris 无 per-light shadow pass API)→ 手电用不了。这就是"shaderpack 格式的天花板"。 |
| Screen-space raymarch(SSO) | 可用但**本质是 AAA 里的降级方案**(SSAO 同族):只知道屏幕上的遮挡物(屏外漏光)、自遮挡要豁免、有条纹噪声要抖动+软化。**我们项目现在的做法**,踩的 R2/自阴影坑全部源于此。 |
| 体素化 + DDA 步进 | Iris 框架内的最强近似(Rethinking Voxels 类思路):把场景体素化后对手电做体素光线步进。工程量大(需要自建体素缓存),是"升级阴影"的正经候选。 |
| 硬件 RT / 光线查询 | shaderpack 内没有通用 ray query API。Iris 的 shadow RT 只加速 sun shadow pass。**想要任意位置光源的 RT 阴影,就得离开 shaderpack 格式 —— 这正是 Radiance/Caustica 选择重写渲染器的原因。** |

### 3.4 Radiance / Caustica 查证结论(2026-08-30,读 README)

| | Caustica | Radiance |
|---|---|---|
| 本质 | Vulkan 硬件路径追踪,**替换原版世界渲染器**,不是 shaderpack | C++/Vulkan **完全替换 OpenGL 渲染器**,JNI 桥接 |
| 平台 | MC 26.2 + Fabric,仅客户端,NVIDIA RTX + DLSS-RR | 版本/loader 支持仍列为 TODO 第一项,早期 alpha |
| 动态点光源/手电 | README 无任何描述,TODO 里也没有 | README 无任何描述 |
| 成熟度 | "early software, expect bugs" | "alpha",缺 DLSS 运行库直接崩 |

**结论:① 两者都是"掀桌"路线(重写渲染器+硬件 RT),与 Iris/Oculus shaderpack 不可通约,对 1.20.1 Forge + TACZ 项目不可移植;② 它们的路线选择本身佐证了 §3.3 的天花板判断——当社区想把光照做对时,发现 shaderpack 格式不够用,于是重写渲染器;③ 但注意:它们重写渲染器也不是为了手电(连 README 都没提动态光源),是为了全局正确性。手电在传统管线(AAA deferred + spot shadow map)里 2007 年就解决了。**

### 3.5 对"要不要抛弃 oculus"的直接回答

**不需要,也不应该。** 理由:
1. 抛弃 oculus 的三条出路——Radiance/Caustica(不可移植,版本/loader/生态全错)、自研 core shader(vanilla 前向管线,无 deferred,做不了我们已经在做的事)、mod 侧自渲染场景(= 把光影包做的事搬到 Java 里,复杂度更高还失去光影包生态)——没有一条比现状好。
2. TACZ 的 PBR 材质需要被光影包解析(LabPBR 约定),留在 oculus 生态是兼容它的最短路径。
3. 我们缺的不是"换框架",是把已有框架里四个子问题逐项做对(§5)。

## 4. 点光源 vs 聚光灯:为什么"顺手一改"不成立

用户此前的直觉:"shader 包都能支持点光源,沿点光源改改就能出聚光灯"。拆解:

| | MC 生态的"点光源" | 聚光手电 |
|---|---|---|
| 本体 | lightmap 烘焙亮度(DLR 系)或 held-light uniform(Complementary/BSL 的持灯) | 真实光源:位置+方向+锥角+衰减 |
| 方向性 | 无(标量场) | 有(内外锥) |
| 遮挡 | 无(lightmap 天然无遮挡;held-light 也只做表面 N·L,没有影子) | **必须有**(否则穿墙) |
| 体积 | 无 | 光束要 march + per-step 可见性 |
| 缓存 | chunk 缓存,静态 | 每帧重建 |

所以"点光源"之所以便宜,是因为它**砍掉了方向、遮挡、体积**——聚光灯要做的恰恰就是把这三样加回来。加方向是一行代码,加遮挡是架构活。这就是"看似顺手、实则换血"的原因。

## 5. 我们项目在原理坐标中的定位

| 子问题 | AAA 正解 | TacLight 现状 | 差距 |
|---|---|---|---|
| 1 锥形直接光 | deferred light pass, N·L | **有**(M1 composite,SSBO 传光位) | 能量未标定(R1 过曝:atten(8m)≈0.94,室内无衰减感,多链饱和);TP 相机自遮挡豁免缺失(R2);天气 pass 破 GBuffer(R3) |
| 2 镜面高光 | GGX + PBR 材质 | **无** | M1 只做漫反射。这是 TACZ PBR 兼容的前置缺口 |
| 3 可移动阴影 | per-frame spot shadow map | **降级方案**(SSO 16 步屏幕空间 raymarch,IGN 抖动,自遮挡豁免球) | SSO 本就是近似;R2 豁免缺口、R5 噪声偏硬(16 步 + 消光 2.4)是"降级方案没做干净",不是选错 |
| 4 体积光束 | raymarch inscattering + per-step V | **有**(M3,24 步,HG g=0.55,IGN 抖动) | 衰减公式复用表面光且无近场正则化(R4:0.35m 灯锚 → 1/r² 爆炸);TP 枪灯锚点错 |
| 时域稳定 | TAA/历史缓冲 | 抖动无时域滤波;EXPOSURE_LOCK=1 已锁自适应曝光 | R5 已编译期排除,自适应曝光解锁前需时域方案 |
| 多人 | — | **数据通路已实现**(M5:SynchedEntityData + 网络包 + 远端灯上传,282 项契约测试全绿) | 实机视觉验收未跑(工具已备:mp-session.ps1) |

**诊断:架构方向(composite deferred + SSBO)不是问题,不需要推倒。** 一直拿不出手的原因按贡献排序:
1. **能量单位从未标定**——半径 56、衰减 k=2/r²、BEAM_GAIN 8.0 这些数字是拍的,不是从"8 米外墙面应回到环境亮度"这类物理陈述推的 → R1 过曝毁了所有质感;
2. **把降级方案当正解交付**——SSO 的三个固有缺陷(屏外漏光、自遮挡、条纹)没有逐个"做干净"就叠了 M3/M2;
3. **边界没有清剿制度**——天气破 GBuffer(R3)、第三人称豁免缺口(R2)都是"主路径对了,支路漏了";
4. 工程事故消耗(手性反转、坐标漂移)占用了本该用于上面三条的时间。

**元问题的回答:是的,应该用 3D 图形学理论指导——但落地不是"读理论",而是改工作循环**:每个特性先回答三个问题(渲染方程哪一项?误差源是什么?用什么截图/数字验证?),再动手。0830 缺陷报告的 §7 五分钟证伪协议就是这个循环的雏形,应该推广为默认流程。

## 6. TACZ PBR 兼容意味着什么(为将来)

- TACZ 枪械用 PBR 材质(法线/高光贴图,LabPBR 约定),这些贴图要"生效"必须有光影包在 gbuffer 里解析它们并喂给光照模型——vanilla 渲染下 PBR 贴图只是数据,没人消费。
- 对 TacLight 的具体含义:子问题 2(specular)的落地路径 = 在 `gbuffers_*` 解析 LabPBR specular 贴图(smoothness/F0/emission 通道)→ M1 光循环加 GGX 项。这一步同时服务"手电照枪的高光"和"场景任意 PBR 方块",不是 TACZ 专属工作。
- 顺序建议:先修 R1–R3(能量/遮挡/天气),再上 specular——过曝不除,高光会糊成一团白。

## 7. 路线建议(汇总)

1. **阶段一·修复**(= 0830 报告 F1–F5,待批):清剿已有三项的缺陷。F1 天气 → F2 自遮挡豁免 → F3 能量标定(观感最大改善);F4 近场正则化、F5 噪声软化为打磨项。
2. **阶段二·补缺**:M1 加 GGX specular + LabPBR 解析(服务 TACZ + 场景质感)。
3. **阶段三·阴影升级(可选,预研)**:体素 DDA 遮挡是 Iris 框架内的正解候选;硬件 RT 路线只做只读学习(读 Caustica/Rethinking Voxels 源码),不投入——shaderpack 内无 ray query API,投入即撞墙。
4. **不换路线**:留在 Iris/Oculus composite。§3.5 三条出路全劣于现状。
