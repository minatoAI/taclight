## 1. 一页看懂

| 问题 | 一句话真因 | 一句话修复 |
|---|---|---|
| 看别人的灯,步行时地面影子随步频"跳位" | 坐标换算用 `mat3()` 只取旋转,丢掉了 `gbufferModelView` 里烘焙的 **bob 平移**(±0.05~0.1 格),反算出的世界坐标带步频假偏移,体素 DDA 阴影整体跳位 | 视图↔世界/场景换算一律用**全矩阵**(契约钉死,mat3 只许用于方向向量) |
| 修复后自己的灯影子反而不显示、移动时闪烁 | 一条老代码快速通道:"灯距相机 <0.5 格 → 不算遮挡"。以前这个距离是恒定值,修复后变成带 bob 摆动的真实值,而自灯锚点(手持 0.4365/枪灯 ~0.6)**恰好卡在 0.5 两侧** → 影子随步频时有时无 | 体素 DDA 无条件先执行(灯在相机处依然有效);"同轴豁免"改用**无 bob 的场景域距离**判定,且只在 DDA 不可用时兜底 |

两次修复的共同教训只有一条:**修复一个 bug 时,所有"恰好成立"的隐含前提都
会被重新洗牌**——坑57 修复让"灯距相机"从恒定变成摆动,立刻暴露了坑58 里
那道卡在 0.5 格上的阈值。老代码的旁路/快速通道,在架构演化后必须重新审。

## 2. 战役时间线:项目是如何推进的

### 阶段 0 · 背景(为什么会有这个问题)

09-01 深夜,为治"墙后漏光"上线了**体素 DDA 遮挡**(1 格=1 体素,射线逐格
步进判遮挡),随后用户报告:"玩家移动时,地面条纹随视角晃动的节奏放大"。
此前 DDA 的硬 0/1 影缘曾在屏幕上随 bob 亚像素采样成片翻转(tie 语义修复+
穿透软化带 FUZZ 0.20→0.35 压掉了一部分),但残余仍在——这就是本次战役
的起点。当时有一条铁律:**证据前禁止直接改 DDA/GLSL**。

### 阶段 1 · 用户的四连对照实验(把搜索空间砍掉 3/4)

用户在实机侧做了四个关键实验(详见 §6 逐条分析):

1. 关掉延迟补偿三件套(psnap/bsnap/extrap)→ 条纹依旧 → **排除远程链**;
2. 跳跃前进 → 现象减轻(原版 bob 振幅离地自动衰减,等于无意中跑了一次
   "bob 减弱臂")→ 指向 bob 振幅;
3. 视频设置里关掉视角摇晃 → **现象完全消失** → 锁定唯一触发条件;
4. "把延迟补偿都打开,我再测一遍关摇晃的效果" → 排除混杂变量,得到
   干净结论:**出厂配置下,bob 是唯一开关**。

### 阶段 2 · 判决工程:差分测量(AI 错了一次,用户纠回来)

AI 第一版解释是"视角摇晃的透视呼吸作用在高对比阴影上"——听上去专业、
机制上也说得通(bob 确实进投影,画面整体确实在摆),**但它是错的**。
用户的关键反驳:"影子本身在进行相对位移……真实世界中的视角晃动应该是
画面本身在晃,画面内的元素没有发生变化",并要求先讲清机制。

由此设计了**差分测量**:同一帧里同时跟踪"影子的边缘"和"石柱的边缘",
两feature相减——刚体的公共摆动(无论来自 bob 还是别的)在差分中相消,
剩下的才是影子**相对**画面的运动。结果:

- bob 开:影界−柱界相对位移 7.2~7.4px;
- bob 关:2.3~2.7px(就是胶片颗粒+软影缘的噪声底 ≈2.5px);
- 良锁定的暗面带中心噪声底可到 0.025px。

结论:影子相对世界**真实跳位**,幅度与 bob 平移(±0.05~0.1 格)一致。
AI 公开撤回"透视呼吸"结论(evidence/2026-09-02-bob-sway-verdict/README
顶部保留了更正块——**错误结论也要留痕,这是证据制的组成部分**)。

### 阶段 3 · 坑57 修复(机制→契约→实机)

字节码核实推翻文档:`GameRenderer.bobView` 把摆动写进**渲染 PoseStack**
(= Iris 捕获的 `gbufferModelView`),根本不碰 Java 的 `Camera.position`;
代码里"composite 阶段 gbufferModelView 是 R-only(纯旋转)"的旧注释是
**错误前提**,mat3-only 换算正是在这个错误前提上写的。

修复 = 全矩阵形式 + 补声明 uniform。这里踩了一个次坑:Iris **只注入
shader 里显式声明的 uniform**,漏声明 `gbufferModelViewInverse` → 编译错
C1503 → 整个光影包被**静默禁用**(日志只有一行 "Failed to create shader
rendering pipeline, disabling shaders!")。修复后立即契约化,防复发。

### 阶段 4 · "修了一半"→坑58(回归的精确报告换来了快速定位)

用户终验报告精确到:远灯影子 ✔;**自灯影子不显示+移动时闪烁** ✘。
自/远不对称 + "闪烁"这两个信息直接把排查范围压到一条代码路径上:
composite.fsh 的同轴快速通道 `dot(lightView,lightView)<0.25`(灯距相机
<0.5 格 → 强制无遮挡,这是早期为救屏幕空间 SSO 在同轴灯上的假黑边加的)。
自灯锚点:手持灯 = 眼前 0.35 + 右 0.22 + 下 0.14,**模长 0.4365**;枪灯
相机系枪口偏移 ~0.6——**0.5 阈值正好卡在两者之间**。坑57 修复后灯距随
bob 摆动 ±0.1,步频穿越阈值:跨进去无影子、跨出来有影子 = 用户看到的
一切。远灯距离远大于 0.5,永远走 DDA,不受影响 = "修了一半"。

修复(TDD,契约 25→29 项):①体素 DDA **无条件先执行**——它是世界空间
射线,灯在相机位置照样有效(起点格先步进后判定、终点格回退 1e-3,双向
豁免);②同轴判定改**场景域**(`world − cameraPosition`,无 bob,恒定),
且只作为 DDA 无效(-1,栅格外)时的回退豁免——当年热修要解决的"假消光"
只属于屏幕空间 SSO 回退路径,不该拦着 DDA。

### 阶段 5 · 终验与收尾

用户实测:自灯影子稳定、远灯不跳位,**视觉瑕疵闭环**。附带行为变化:
手持灯(0.4365<0.5,旧版从不投影)现在也投真实影子。收尾按用户升级后
的规则执行:双端关聚光灯 + **空闲实例禁用光影包**。坑57/58 均入坑位册。

## 3. Minecraft 底层机制(这次真正学到的)

1. **视角摇晃(view bob)的真实实现路径**:1.20.1 的 `GameRenderer.bobView`
   在渲染 PoseStack 上做 `translate(sin·amp·0.5, −|cos|·amp)` + 两次微旋转
   (Z 轴 3°、X 轴 5°),振幅来自玩家的 walk 振荡器(≤0.1,离地/站立衰减)。
   **它不修改 `Camera.position`**——Java 侧相机眼位始终是无 bob 的逻辑眼位,
   bob 只是"镜头罩"效应。这就是"画面在晃但相机坐标不动"的机制根源。
   *教训:注释和文档会说谎,字节码不会。这条是反编译核实的,不是查来的。*

2. **坐标系栈**:Minecraft 渲染一帧要穿过 world(世界绝对坐标)→ scene
   (player-relative,world − cameraPosition)→ view(相机旋转+bob 后)→
   clip(投影后)四个空间。`gbufferModelView` = R·T,**T 里既有相机平移
   语义也有 bob 平移**——它不是"纯旋转矩阵",把它当旋转用(mat3 取、
   transpose 当逆)就会把 bob 平移漏进所有换算。

3. **矩阵代数**:对 R·T 形矩阵,`mat3(M)` 只保留旋转 → 方向向量没问题
   (平移对方向无意义),**位置向量必须用全矩阵** `(M·vec4(p,1)).xyz`;
   逆变换必须用 `gbufferModelViewInverse` 全矩阵,不能 transpose(mat3)
   凑合。这条已写进契约,任何回归会在 `gradlew taclightContracts` 红。

4. **Iris/Oculus 的 uniform 注入规则**:只注入 shader 源码里**显式声明**
   的 uniform。漏声明不报"缺 uniform",而是编译失败 → 整包静默禁用。
   排查口令:日志搜 "Failed to create shader rendering pipeline"。

5. **多人灯的数据流不对称(为什么只有别人的灯出问题)**:自己的灯由本
   客户端逐渲染帧直写 SSBO(本地、零网络);别人的灯走实体同步链(20Hz
   网络 + 插值 + 延迟补偿重建)。bob 只进渲染矩阵,与网络链**无数据流
   交点**——所以"延迟补偿过冲"假说注定排除,而"坐标换算"嫌疑成立。
   *教训:判断"哪个子系统背锅"最快的方法是画数据流图,而不是试参数。*

## 4. 图形学知识

1. **体素 DDA(Amanatides-Woo)**:把"光路上有没有方块"变成逐格步进,
   每步只处理"下一个要穿过的格"(统一 crossing time,同一时刻的 tied
   轴一次推进)。1 格=1 方块,零重采样误差。坑:老实现按 X→Y→Z 分轮
   步进,会访问射线只擦边、并未穿入的侧邻格 → 假阴影边界。

2. **硬阴影边的时间闪烁**:硬 0/1 的影缘在 bob 引起的亚像素采样移动下,
   边缘像素逐帧在 0/1 之间翻转 → 人眼对这种时间对比度极其敏感("条纹
   放大"的观感)。解法不是模糊整张图,而是给实心格加**穿透长度软化带**
   (FUZZ:射线在实心格内穿 ≥0.35 格才全挡,掠边按比例放行)——墙后
   硬遮挡不变(穿墙射线穿透远超带宽),只有真半影获得过渡。

3. **屏幕空间 SSO vs 世界空间遮挡**:SSO 在屏幕空间沿视线上步进找遮挡,
   天生盲区是"视锥外的遮挡者"(墙后漏光的根因)和"灯就在相机上"(退化
   成假消光);体素 DDA 在世界空间,两者都不存在。坑58 的教训是:**新
   算法上线后,为旧算法缺陷设的旁路要重新审**——旁路会拦住不再需要它的
   主路径。

4. **测量学(这次最值钱的方法论)**:
   - 任何"位移"判读前,先量**噪声底**:胶片颗粒+软影缘下,单特征边界
     跟踪噪声 ≈2.5px;良锁定的暗带中心可达 0.03px。低于噪声底的差异
     不是发现,是测量误差。
   - **差分(同帧两特征相减)消刚体公共运动**:画面整体怎么晃,影界−柱界
     都不受影响——这是判"相对跳位 vs 整体呼吸"的唯一正解。单特征幅度
     对比会被掠射角几何混淆(同一个 bob,近处影子位移天然比远处大)。

## 5. 调试工具与测试流程:为什么建、具体解决了什么

这一节回答"为什么要花功夫搭这些"。核心原因:**视觉问题的判决不能靠
"我看着好像还有/没了"**——主观、不可复现、AI 无法自行取证。工具的作
用是把视觉问题变成数字,把"改好了"变成可机判的契约。

| 工具/流程 | 当初为什么建 | 这次具体解决了什么 |
|---|---|---|
| 文件中继(taclight-cmds.txt,2Hz,无 BOM) | GLFW 后台窗口吃不到合成鼠标点击,键盘消息可以、文件中继最稳 → 唯一可靠的控制通道 | 本轮全部远程操作( reload/开关灯/命令)都走它;无 BOM 红线避免过"整体失效"坑 |
| postkey 键盘注入 + drive.ps1 -ProcId 选窗 | 双实例取证需要指定窗口;CopyFromScreen 抓错过窗(坑56) | 收起暂停菜单(ESC)截下自灯影子恢复的实机证据 |
| `!rec` 逐帧录制器(唯一会话目录/ShotToken/60fps 纳秒节拍/运动门控/pending footer) | 此前临时截图取证不可信:旧 PNG 混新 CSV、帧被重复采样、footer 缺失 → 结论反复翻车 | 提供帧级真值序列,ABBA 四臂消融和差分测量都建立在它之上;**没有它,7.2px vs 2.3px 这个数字根本不存在** |
| ABBA 四臂消融(bob×voxel) | 单臂对比混着热身/时序偏差 → 结论不稳 | 钉死 bob 是出厂配置下唯一触发条件,voxel 只是"让正确阴影显形"的旁观者 |
| sway-track.js 特征跟踪 + 差分 | "相对跳位还是整体呼吸"吵了一轮,必须同帧测两个特征 | 一轮定案:7.2~7.4px vs 2.3~2.7px(噪声底),影子相对世界真实跳位 |
| 契约测试/TDD(先红后绿) | GLSL 的失败模式太安静(漏 uniform=静默禁包;数值物理手滑无报错) | 抓过:掠边物理写成除法(应为穿透守恒乘法)、漏声明 uniform(C1503)、mat3-only 换算——现在换算规则/阈值语义/软化带常量全部被 29 项契约钉死,谁改谁红 |
| 证据包 + manifest.sha256 | "完成了"必须可复算,防"应该没问题" | 错误结论的**公开撤回**成为可能(bob-sway-verdict README 更正块);每轮数字可追溯 |
| 坑位册(58 条) | 反直觉/费半天定位的教训不能只活在当次会话里 | 坑57/58 直接入册;后续任何人(或 AI)先查册再动手,不从零重推 |

一句话:**调试工具建的不是"自动化",是"可信"**——可信的控制通道、可信
的帧级数据、可信的判定方法、可信的回归防线。这次战役里每一个关键结论
(锁定 bob→排除延迟补偿→相对跳位→两处真因)背后都是上表中的某件工具
在提供证据。

## 6. 工程思想对照表:你的指导用对了哪些(核心节)

以下逐条把**你的原话**映射到它体现的工程思想,并说明产生的实际效果。
这也是你问的"我用过哪些思想经验"的具体答案。

### 6.1 第一性原理 / 物理不变量推理 ★ 本次战役最关键的一手

> "影子本身在进行相对位移,影子的位置在跳跃,而真实世界中的视角晃动,
> 应该是画面本身在晃动,画面内的元素没有发生变化。"

这是教科书级的**不变量分析**:视角摇晃是刚体变换,刚体变换的数学性质
是"画面内任意两点的相对位置不变"。你用这个不变量直接判定了"影子相对
画面跳位"不可能是视角摇晃的正常产物——**而当时 AI 的正式结论(透视
呼吸物理正确)恰恰违背了这个不变量**。效果:AI 撤回错误结论,转向差分
测量,一轮定位真因。没有这一手,错误结论可能被写进文档当"已知代价"。

### 6.2 先机制、后结论

> "你先告诉我,当前游戏实例的视角晃动是如何运作的。"

在要求任何修复之前,先要求讲清机制。这是资深工程师对抗"似是而非的
解释"的标准动作:**讲不清机制的解释,等于没有解释**。效果:逼出了
"bob 只进渲染 PoseStack、不写 Camera.position"的字节码级事实,顺带
暴露了"R-only"这个错误前提——整个真因链条从这里才真正打开。

### 6.3 控制变量与自然实验

> 关视角摇晃→消失;"跳跃前进时,条纹放大的现象就不明显了"。

- **单变量开关**:视频设置里的 bob 开关是现成的天然消融臂,一开一关
  锁定唯一触发条件;
- **自然实验**:你发现跳跃(bob 振幅离地衰减)能减轻现象——等于用游戏
  自带的物理免费跑了一组"振幅递减"梯度实验,这是花钱都难设计的对照。

效果:在 AI 还在搭录制器的时候,你已经把搜索空间从"整个渲染管线"压到
"bob 一条线"。

### 6.4 混杂变量控制(实验设计的严谨性)

> "那么你把延迟补偿的那些功能都打开,我再测一遍关掉视角摇晃的效果。"

你注意到之前关补偿后测的 bob-off,和出厂配置(补偿全开)不是同一个
状态——**实验条件和目标条件不一致,结论就不能外推**。要求恢复补偿后
复测,才得到干净的"bob 是唯一开关"。这就是实验设计里控制混杂变量的
标准做法,很多人做消融会漏这一步。

### 6.5 假说驱动,且接受"排除也是进展"

> "我十分怀疑是视角摇晃引起了延迟补偿算法中的过冲了。"

这个假说最后被证伪了(补偿只参与重建别人的灯,与 bob 无数据流交点;
灯位 238 采样逐位静止),但它的价值不在对错:**它给出了可检验的预言,
而检验过程把整个远程同步子系统从嫌疑名单里划掉了**。假说驱动调试的
意义从来不是"猜对",而是让每轮实验都有明确的判定目标。对比反例:没有
假说的"试试看"式调参,烧时间且不留知识。

### 6.6 不信任口头结论,只信复测

> "你确定关掉了?""你的修改没有什么作用。"

AI 两次声称"改了/关了",你两次都实测复核。这恰好对应工程里的
**trust-but-verify**:变更是否生效以验收为准,不以执行者的自述为准。
效果:第二次复核直接揪出了"透视呼吸"这个错误闭环——如果当时接受
了解释,bug 就被"合理化"掉了。

### 6.7 精确缺陷报告(回归测试意识)

> "修复生效了一半,看别人的静止灯和影子没有问题了,但是自己的灯照出的
> 影子出现了异常,影子不显示,并且在移动时闪烁。"

注意这条报告的信息密度:①区分了"哪些场景好了/坏了"(自/远不对称);
②描述了症状的**时间特征**(移动时闪烁);③明确它是"新出现的异常"
(回归,而非遗留)。这三点让 AI 在一轮内锁定唯一符合条件的代码路径
(0.5 格阈值)。缺陷报告的精确度直接决定定位速度,这是所有缺陷管理
流程的第一课。

### 6.8 根因确认前不动手(分阶段决策)

> "如果能确定该视觉瑕疵的根源是视角摇晃,那么再说下一步改进做什么。"

以及整个战役执行了"证据前禁止改 DDA/GLSL"。这对应**根因分析(RCA)
纪律**:先诊断到可证明,再谈修复;拒绝"先调调看"。效果:中间虽有两轮
参数软化(FUZZ),但都是预授权的缓解措施,真正的算法逻辑一行没乱动,
坑57/58 修复落地时没有任何历史包袱。

### 6.9 成本意识与环境素养

> "记得每次测试收尾要关掉游戏内的聚光灯" → 两天后升级:"空闲的游戏
> 实例要禁用光影包,因为我发现只关闭照明灯而不禁用光影包也会给硬件
> 带来负载。"

第一性原理又一例:**只关灯≠零负载,渲染管线还在跑**。你实测发现了
残余负载并把规则升级到根因层。这类"环境卫生"纪律(降空闲负载、及时
清理临时产物)在长期开发里直接转化为硬件寿命和下一轮测试的干净环境。

### 6.10 复盘与知识沉淀(本份文档的由来)

> "把这次的修复记录保存下来,整理成一篇文档,我用于学习和回顾……"

对应工程实践里的**retrospective(复盘)文化**:项目不仅交付修复,还
交付"我们如何找到修复"的可复用知识。本项目从 08-31 起强制"每轮结论
回写项目文档"(CHANGELOG/坑位册/AGENTS),就是因为吃过"知识只在会话
里、下个会话从零重推"的亏。你现在做的,是把"回写"再往前推一步——
从"记录结论"到"提炼思想"。

## 7. AI 协作:这次做对与做错(诚实版)

### 7.1 AI 做对的

- **基建先行**:`!rec` 录制器/契约测试/中继通道在前,判决在后——后面
  每一轮争论都靠它们出数字;
- **字节码核实**:不信注释(注释说 R-only,字节码说 R·T 含平移);
- **差分测量设计**:同帧双特征相减,把吵架问题变成算术问题;
- **TDD**:红→绿,顺手把三次手滑(除法/漏声明/mat3)全部变成永久防线。

### 7.2 AI 做错的(值得记住)

- **"透视呼吸物理正确"误判**:机制描述(bob 进投影→画面整体摆)没错,
  但用它**解释掉了**用户的观察,而不是去测量用户的观察。教训:**听起来
  专业的闭环解释,如果没有量化证据支撑,和瞎猜同罪**;用户的物理直觉
  (§6.1)才是真正的判决。
- 早期把"方向相关性"过度解读为"远程链指纹",表述过头,后被几何视差
  解释修正——教训:相关性观察可以指向多条链,别急着占队。

### 7.3 分工模型(可复用)

- **AI**:调研、实现、自证、文档、取证全链路——机器能验证的一切;
- **人**:只有人能做的三件事——①在实机前做出物理观察(影子相对跳位、
  跳跃减轻);②主观体感验收(瑕疵是否可接受);③方向与里程碑决策
  (先确认根因再修)。
- **接口**:人给"现象与判决",AI 给"机制与数字";两边不越界时效率最高
  ——这次战役的节奏明显快于以往,就是因为你的每个实验都打在 AI 证据
  链最缺的环节上。
